## 背景

整体缩放（ADR 0057）落地后，真机（Windows 11，1600×1000 / 工作区 1600×952）发现一个观感问题：

> **1.0x 默认倍率下，拖拽角色左右摇晃时，头发和身体边缘会被窗口边缘切掉（出屏）。**

原因是窗口尺寸与正交视锥一直只按模型的**静态包围盒 × 1.15** 算：

- 那个 1.15 的留白**全在头顶**（94px），左右各只剩 **27px**；
- 而拖拽时她是**绕抓取点的单摆**（ADR 0035 D2/D3），整身转起来，头顶的留白一点用都没有，
  横向几帧之内就把发梢顶出内容区。

## 排查（真机 + 离线实测）

### 1. 侧影不是包围盒：本资产的形状是"髋部最宽、脚很窄"

用 `tools/glb-silhouette.mjs` 直接读 `CH0335.glb` 的顶点（不蒙皮，绑定姿态就是建模姿态），
按高度分 16 带求每带 `[minX, maxX]`，换算到 1.0x 的 CSS px（脚底为原点）：

| 高度 y（px） | 左（px） | 右（px） | 宽度 |
|---|---|---|---|
| 535（发顶） | -64 | +64 | 128 |
| 468 | -91 | +91 | 182 |
| 402 | -95 | +95 | 190 |
| 334 | -120 | +120 | 240 |
| 268 | -171 | +171 | 342 |
| **234（髋/长发最宽）** | **-183** | **+183** | **367** |
| 168 | -172 | +172 | 344 |
| 134 | -165 | +165 | 330 |
| 100 | -139 | +139 | 278 |
| 67 | -66 | +66 | 132 |
| 33（脚） | -67 | +67 | 134 |

结论有两条：

1. **包围盒四角是假的**。包围盒在脚底那一行也是 ±183，而真实的脚只有 ±67。
   用四角做"旋转后会不会出画"的判定，抓头单摆只能摆到 **≈0.12rad（7°）**；
   用上面的真实侧影可以摆到 **≈0.28rad（16°）** —— 差一倍以上。
2. **窗口只比模型宽 27px**，而单摆位移是 `py·sinθ`（`py` ≈ 抓取点到脚底的距离，头部抓取 ≈370–465px）：
   0.2rad 就有 75–95px 的横向位移。

### 2. 悬空片段本身就比站立宽，而且带根位移

把 `Formation_Pickup` 播起来之后逐帧量"她整块"的 CSS 包围盒（`silhouetteCss()`）：

| 状态 | 侧影宽度 | 中心偏移 | 最低点 |
|---|---|---|---|
| 站立待机 | 367px | 0 | 0（贴底边） |
| 悬空（`dragged`） | **≈462px**（±231） | **偏左 ≈50px** | **沉到地线以下 8–21px** |

也就是说：**光姿态本身就吃掉了左右各 36px 的余量**，再叠加摆角位移必然出画；
而"沉到地线以下"就是真机截图里"靴子被底边切掉一截"的那一条。

### 3. 缩放锚点会累积取整误差

`applyViewScale()` 原来每次都从 `getContentBounds()` 现算锚点：
`x = round(anchor − w/2)` 在宽高为奇数时会带 ±0.5px 误差，下一次缩放再拿这"半个像素"当基准，
连续缩放一轮后窗口漂了 **2px**（自检"还原 1.00x 后窗口回到原位"因此失败）。

## 决策

### D1. 视口安全边距：`MODEL_VIEW_PADDING_PX = 36`（上）、`MODEL_VIEW_PADDING_X_PX = 64`（左右）

窗口内容区 = **静态包围盒 ±15%** 之后再**加**边距：

- 高度 = 设计高 720 + 36（头顶）；
- 宽度 = 包围盒推导宽 + 2 × 64；
- **底边 0**：契约 §1.2 的锚点就是"窗口底边中心 = 她脚底"，加了下边距脚底就离地，
  吸附/落地/行走/坐姿的坐标系要全部重算（明确不做）。

1.0x 因此从 `422 × 720` 变成 **`550 × 756`**，而 `pixelsPerUnit` **仍然是 57538** ——
她自己的像素尺寸一点没变，多出来的 128 × 36 是真正的透明空白。

为什么左右比上下大 28px：D2 的第 2 条（悬空姿态 462px 宽 + 偏左 50px）只有横向需要覆盖；
头顶本来就有 15% 留白（94px），加 36 之后是 130px，足够呼吸与微动。这个差额是有实测依据的，
不是"随手给大一点"。

### D2. 边距是**加法**：`pixelsPerUnit` 只与内容高成正比

`pixelsPerUnitFor()` 增加 `viewPaddingShare`（= `36 / (720+36)`）参数：先把内容高按份额折回
"纯取景高度"，再算像素比。于是：

- 1.0x 时 `pixelsPerUnit` 与加边距之前**逐位相同**（57538），且与内容高严格成正比
  （2.0x 就是 2.000x，不会因为"减 36px"而偏 0.3%）；
- 缩放仍然是"改窗口"，渲染侧只响应 `resize`，不引入任何模型缩放。

### D3. 拖拽摆角由**真实侧影**约束（`maxSwingAngle()`）

`drag-motion.ts` 新增两个纯函数：

- `swingFits(points, pivot, angle, viewport, safety)`：绕支点旋 `angle` 后，所有侧影点是否
  仍在内容区矩形内（含 `pivotCompensation()` 的等价效果）；
- `maxSwingAngle(...)`：在物理上限（`DRAG_PENDULUM[band].angleLimitRad`）内线性扫描 + 二分，
  返回可行最大角；侧影缺失时返回**兜底下限** `DRAG_SWING_MIN_ANGLE_RAD = 0.06`，
  绝不返回 0（否则拖拽会退化成整身硬平移）。

侧影来源是 `measureSilhouette()`（加载时测一次，16 带，每网格 8192 点，root 局部单位）。
**拖拽期间再重采样 4 次**（`DRAG_SWING_RECALIBRATE_MS = [220, 550, 900, 1400]`，每次 2048 点）：
悬空片段的头发会继续往外甩（实测 0.2s 时 ±182px、1.4s 时 ±221px），一次测量盖不住。
每次测完把新点**并入**已有集合（只增不减），于是上限只会往下收，不会来回抖；
上限本身按 `DRAG_SWING_LIMIT_SMOOTH_MS = 120` 指数收敛，避免"突然少转几度"的抽搐。

实测结果：1.0x 下 `swingLimit` 保持 **0.35（物理上限）** —— 边距足够，**不需要夹**；
只有抓在最靠上的头发/光环（支点更高）时才会收到 0.24–0.27。

### D4. 悬空姿态的下沉补偿 + "被拎离地"最低高度

`calibrateDragPose()` 在 220ms 时量一次"最低点沉到地线以下多少"，然后
`dragLiftTargetPx = 下沉量 + DRAG_LIFT_MIN_PX`（32px × 当前比例），按 100ms 指数跟上、
随 `dragPoseGain` 淡出。

`DRAG_LIFT_MIN_PX` 不是审美微调，而是**几何必需**：绕抓取点转 θ 时脚一定会往下扫
（支点在头顶、脚在下方 465px，θ=0.27 时左脚要沉到地线以下 ≈32px）。只补"片段造成的下沉"时，
侧影的竖直判定会把摆角上限压到 **0.02rad**（等于没有单摆，实测踩到过）。

副作用（可接受、也符合直觉）：被拖起来时她离地约 32px，"被抱着"本来就不该踩在地上；
抓取点因此相对光标上移 ≤32px（626px 身高上的 5%），肉眼几乎无感。

### D5. 缩放锚点只在"被别的东西搬动过"时才重取

`applyViewScale()` 记住上一次提交的逻辑锚点（`viewAnchor`）；只有当窗口当前位置与
"上次锚点推出的位置"相差 > 2px（= 拖拽/行走/吸附/D-7 兜底搬过它）时才从当前 bounds 重取。
连续缩放不再累积取整误差（自检"还原 1.00x 后回到原位"±1px 通过）。

### D6. 工作区夹取**保持**（用户拍板）

缩放上限仍然 `min(请求, 工作区能装下的最大比例)`：**绝不允许头顶出屏**，
也绝不允许窗口长到工作区外面之后拖不回来。代价是 1080p 桌面上 2.0x 实际只能到
`952/756 ≈ 1.26x`，面板状态页会显示"2.00x → 1.26x（受屏幕限制）"。

### D7. 自检里"落座弹簧/阶段 B"的判据改成整段不变量（提交前修掉三条 flaky）

收尾复跑时主链路出现过 **3 条偶发失败**（前一天同代码全绿），全部集中在坐姿时序上：

| 断言 | 失败现象 | 根因 |
|---|---|---|
| 落座时有半蹲过渡 | `sit.transition=1`、`transitionLiftPx=0` | 判据取"`arrived` 那一帧"的**重快照**，而 `getDiagnostics()` 单次 ≈300ms —— 弹簧只有 ≈0.3s，采样可能整个落在它之后 |
| 补偿 offset ≈ raw × sitPoseGain | `sitPoseGain=0` | 同上（同一帧读到的是弹簧起点或终点） |
| 阶段 B 在 0.3s 内收到 1 | `stageBAtMs=813`（要求 ≥900） | 实际在测"采样起点是否早于 16.0s"，与产品行为无关，随前序步骤耗时漂移 |

改法（断言**更严**，不是放宽）：

1. `sitSequenceDiagnostics()` 增加 `offsetPx` / `rawOffsetPx`（O(1) 拷贝，仍在内部诊断里）——
   于是"补偿 = 原值 × 增益"可以在**同一时刻**读三个量。
2. 落座**从接近阶段就开始**用 16ms 轻快照采样 3.2s（不阻塞主流程，阶段 A/B 采完再取回），
   断言改为整段不变量：`sitDrop ∈ (0,1)` 被看到 ≥3 帧、抬升 `(1−sitDrop)×sitPoseGain > 0.05` ≥2 帧、
   16ms 步进 <0.35；补偿在**每一帧**都满足 `offset ≈ raw × gain`（±1.5px，实测最坏 0.21px），
   且增益确实经过 `(0.15, 0.85)` 中间态 ≥2 帧。
3. 阶段 B 改成测**过渡时长**：`stageBBlend` 从 ≤0.02 到 ≥0.98 的 Δt 必须落在 150–700ms（实测 249ms）。

### D8. 自检桩的端口改为**启动前动态探测**

真机复跑时语音/视觉两套自检 `exit 1`，但断言本身 33/0、16/0 —— 日志里是
`LLM 桩无法监听 127.0.0.1:11435（EACCES）`。查 `netsh int ipv4 show excludedportrange`
发现 Windows 的**端口排除范围是动态的**：那次重启后 `11367–11466` 被 Hyper-V/WinNAT 整段占掉，
写死的 11435 因此绑不上（断言全过、进程退出 1，最难一眼看穿的那类"红"）。

改法：`scripts/start.mjs` 在**拉起 Electron 之前**对候选端口逐个试绑（`net` 监听再立即关闭），
把能用的那个写进 `PET_LLM_URL` / `PET_TTS_URL` / `PET_OCR_URL` 与 `PET_SELFTEST_*_PORT`；
`selftest-stubs.ts` 从环境变量取端口（常量只作兜底），启动后打一行
`本地桩已监听 127.0.0.1:<llm>/<tts>/<ocr>`。实测本次 llm 自动落到 **12435**。

## 被否决的方案

| 方案 | 否决原因 |
|---|---|
| 只加 36px 边距、不做摆角约束 | 实测仍会在 0.2rad 以上把发梢切掉（1.26x 下尤其明显），而且悬空姿态本身就吃掉 36px |
| 用包围盒四角判"会不会出画" | 脚底那一行的假角落把摆角压到 7°，等于砍掉一半单摆 |
| 拖拽时把窗口临时加宽 | 窗口位置由拖拽跟随光标定义，中途改宽要重算 origin、掩膜与吸附坐标系；风险远大于收益 |
| 拖拽时把她整体缩小（如 0.92x） | "被拎起来会变小"是可见的伪影，且会与 `pixelsPerUnit` 的语义打架 |
| 用掩膜 alpha 当侧影实时约束 | 拖拽期间掩膜采集按 R-8 暂停；恢复它等于推翻 R-8 的省 GPU 决策，且有 250ms 反馈滞后 |
| 把她的姿态横向居中（消除 50px 偏移） | 抓取点会相对光标横移 50px，比"发梢离边 4px"难看得多 |

  `npm test` 全绿；`panel:shot` 26/26。
- **提交前连跑两轮主链路自检均为 236/0**（D7 修完之后），语音/视觉在 D8 之后各重跑一次均 exit 0。
- 3.10 实测：内容区 `550×756`、`pixelsPerUnit=57538`（模型像素尺寸不变）；
  抓头摇晃摆角到 **0.273–0.335rad**（`swingLimit` 保持 0.35 未被夹）；
  逐帧侧影全部在视口内；**摆幅最大那一帧的实拍 alpha 包围盒**四周仍有 ≥2px 空白。
- `swing:shot` 取证（`logs/evidence/`）：`swing-100.gif` / `swing-130.gif`（逐帧"录屏"）、

## 已知边界

1. 侧影约束是"**她这一帧的姿态**是否在框内"，不是"保证任何姿态都在框内"：
   若未来换成更宽的悬空片段，重采样（D3）会自己把摆角收小，但**姿态本身**仍可能贴边
   （那时该调的是 `MODEL_VIEW_PADDING_X_PX`，不是摆角）。
2. 摆角约束只在拖拽（`physics=dragged`）期间生效；`settling` 期间角度随 `dragPoseGain`
   淡出，沿用同一个上限。
3. 下沉补偿让抓取点相对光标上移 ≤32px（D4），这是"脚不被切"的必要代价。
