## 背景

阶段 14 封版后真机发现：**角色的手/手臂异常白**，像一块会发光的白板，没有肤色、没有明暗；脸、衣服、头发看起来正常。

要求先量数据再改代码，且不得引入任何按次计费调用（C-1）。诊断分三层：

1. 运行时遍历所有 `SkinnedMesh`：名称、材质名/类型、`map` 是否存在、`colorSpace`、手部顶点数；
2. 离线解析 `CH0335.glb` 的 JSON/BIN：材质、贴图、手部顶点的 UV 与贴图采样值；
3. 运行时对照实验：只把手部顶点染红、整块 Body 材质染红、无光照 ↔ Toon + 光照。

## 诊断事实（2026-11-02，本机 CH0335.glb）

### 网格与材质

| 事实 | 值 |
|---|---|
| 场景网格 | 10 个（`CH0335_Body` 的 6 个 primitive 被 GLTFLoader 拆成 `CH0335_Body_1…6`，加 Halo/Weapon/Prop/brush） |
| 手部所在网格 | **`CH0335_Body_6`**（SkinnedMesh，5548 三角形，材质 `CH0335_Body`） |
| 手部顶点 | **150** 个由 `Bip001 L/R Hand` 主导；**64** 个由 `Bip001 L/R Forearm` 主导（同一网格） |
| 材质类型 | **全部 `MeshBasicMaterial`**（`model-loader.ts` 在加载时统一转无光照；场景中**没有任何** `AmbientLight`/`DirectionalLight`） |
| 材质贴图 | `map` **存在**：`CH0335_Body.png`，512×512，`colorSpace = 'srgb'` |
| 其它 | `vertexColors = true`，`COLOR_0` 全为 1；`color = #ffffff`；无 `emissive` |

因此第一轮就排除了三个常见假设：

- **不是贴图缺失**（`map` 存在且 512²；`map.colorSpace` 已是 `srgb`，GLTFLoader 在 `assignTexture(..., SRGBColorSpace)` 时设置）；
- **不是色彩空间**；
- **不是环境光过曝**（场景里根本没有灯；材质是 unlit）。

### 贴图事实（离线 + 运行时一致）

`CH0335_Body.png` 是**平涂色块**贴图，不是有明暗过渡的插画：

| 项 | 值 |
|---|---|
| 手部顶点 UV 包围盒 | `u 0.282959–0.285400 × v 0.955811–0.957703` |
| 在 512² 下覆盖 | 约 **1.2 × 1.0 texel**（面积 4.6e-6） |
| 该区域采样颜色 | **`#f1edec`**（运行时 `handTextureColor` 与离线逐顶点采样完全一致；三角形面积采样 1552 个样本只有 1 种颜色） |
| 同色块的其他部位 | 骨盆 47.7%、大腿 44.9%、颈/头 16.9% 的顶点也采样到同一色（即：它确实是"肤色"块，但被平涂成接近白） |
| 面部肤色 | `CH0335_Face.png` 的主色 `#f9f1ec`（比手部亮约 3%） |

即：**手不是"没有肤色"，而是"肤色被平涂成了近白 + 无光照材质不做任何明暗"**。脸之所以看起来正常，是因为眼睛、嘴、红晕、刘海给脸提供了结构与对比；手是一整块 `#f1edec`，没有任何细节。

### 对照实验（每张图都落在 `dist/selftest/`）

| 实验 | 结果 | 结论 |
|---|---|---|
| 只把 150 个 Hand 顶点染红（`tintSkin('hand')`） | 红色**精确覆盖**右拳与左侧手部，衣服/腿/脸不变 | 手确实在 `CH0335_Body_6` 上，顶点识别正确 |
| 把 `CH0335_Body` 材质整体染红 | `CH0335_Body_6` 整块（衣服+腿+脖子+手）变红；手部取样 `redRatio` 0.98 / 0.75 | 手与衣服共用同一材质，**不能**用"整块材质换色"来修 |
| 无光照（生产路径） | 手部像素 `(246,239,235)`，**96.6% 近白** | 复现"发光白板" |
| 只给 Body 换 Toon + 灯 | 手部 `(166,162,158)`，有明暗；但外套从白变灰、脸仍是白的 → 脸/身体割裂 | 不可接受（还要新增灯与材质分支） |
| 全部材质换 Toon + 灯 | 手部 `(165,161,158)`，整体一致；但整机偏灰，丢失官方亮色调 | 改动面太大，不是本轮目标 |
| 恢复 Basic | 手部回到 `(247,240,236)`，97.6% 近白 | 证明可逆、对照有效 |

## 决策

### D1 根因 = 平涂贴图 × 无光照材质，不是缺图/色彩空间/过曝

三件事同时成立才会出现"白板"：

1. 身体贴图是平涂色块，手部 UV 只覆盖 1–2 texel，纹理里没有任何可用的明暗信息；
2. `MeshBasicMaterial` 不做光照计算，`COLOR_0` 全 1，材质的 `color` 全白；
3. 手是独立的一块轮廓，周围又是白色外套，缺少脸部那样的结构参照。

**不要**再按"贴图缺失 / `colorSpace` 未设 / 环境光过曝"去修：这三条都已被运行时数据排除。

### D2 修法：只给手/小臂顶点烘焙"暖肤色 × 法线明暗"到 `COLOR_0`

`src/renderer/render/skin-shading.ts` 的 `bakeSkinShading()` 在模型加载后跑**一次**：

```
shade = clamp(ambient + diffuse * max(0, dot(normal, light)), 0, 1)
COLOR_0 = tint * shade
```

- 只写 `Bip001 L/R Hand` + `Bip001 L/R Forearm` 主导的顶点（本资产 214 个）；
- 其它顶点保持 1（模型原始值），衣服/脸/头发**完全不受影响**；
- 不换材质、不加灯、不新增渲染 pass、不增加每帧成本（只在加载期写一次顶点色）。

参数（`DEFAULT_SKIN_SHADING`）：

| 参数 | 值 | 理由 |
|---|---|---|
| `ambient` | 0.78 | 背光面保留亮度，避免整只手变灰 |
| `diffuse` | 0.22 | 只加一层柔和明暗，不做硬阴影 |
| `light` | `(-0.35, 0.65, 0.68)` | 左上前方，与桌面宠物的默认观感一致；+Z 是角色正面 |
| `tint` | `(1.00, 0.90, 0.85)` | 把 `#f1edec` 拉向暖肤色，而不是中性灰 |

实测（以"只染红手部"得到的 5,135 个手部像素为掩膜，跨帧同姿势取样）：

| 版本 | 手部均值 | 近白像素占比 |
|---|---|---|
| 修复前（纯手部像素） | `#f6efeb` (246,239,235) | **96.6%** |
| 修复后（纯手部像素） | `#e1d3ca` (225,211,203) | **0.2%** |
| 诊断用强参数 | `#d7ccc3` (216,205,195) | 1.2% |
| Toon + 灯（对照，未采用） | `#a5a19e` (165,161,158) | 0% |

A/B 对照（同一姿态、同一帧；`setSkinBake(false/true)`；掩膜为 6,000–6,200 个红色手部像素，**含被衣袖遮挡/抗锯齿的边缘**，所以均值比纯手部像素低；手指姿势不同会有几帧抖动）：

| 版本 | 手部掩膜均值（代表帧） | 近白像素占比 |
|---|---|---|
| 烘焙关闭（= 修复前） | `#ded2d0` (222,210,209) | **≈80–83%** |
| 烘焙开启（= 修复后） | `#cebdb7` (206,190,183) | **≈0.1–3.3%**（纯手部像素 0.2%；掩膜含衣袖边缘时会把这部分算进来） |
| 拳头 90×90 取样框（含衣袖/背景） | 近白占比 0.360 → 0.190 | — |

### D3 为什么不用"给手部刷一层肤色贴图"

手部 UV 只有约 1.2 texel，贴图上没有任何空间画阴影/指节；往这张 2 texel 的块里画渐变，等价于给整只手刷一个平色，仍然没有明暗。顶点色是这批顶点上**唯一有足够分辨率**的着色通道（150 个手部顶点 + 64 个小臂顶点）。

### D4 为什么不做全局 Toon 化

Toon + 灯确实能给手明暗，但：

- 只换 Body：外套变灰、脸仍是白的，脸/身体割裂（实测截图）；
- 换全部：整体明显偏灰，丢失官方亮色调；且要为 EyeMouth/眉毛单独开口子，牵动 ADR 0026 的贴图通道；
- 新增灯与第二种材质路径，违背"默认路径零成本、最小改动"的项目取向。

本轮把改动限制在"手/小臂的顶点色"，全局外观与既有材质策略不变。

### D5 可观测与回归

- `RenderDiagnostics.skin`（内部诊断，**不进 `RenderState`**）：`meshes/vertices/minShade/maxShade/meanColor`；
- `window.diagnostics` 新增（仅同页脚本/自检）：`inspectMaterials()` / `tintSkin(scope)` / `shadeSkin(options)` / `testHandMaterial(color)` / `setShading(mode)` / `setSkinBake(enabled)`（A/B 开关）/ `resetMaterials()` / `handScreenPoints()`；
- `PET_HAND_DIAG=1`（配合 `PET_SELFTEST=1`）只跑手部诊断：落 `dist/diagnostics/hand-diagnosis.json` 与 `dist/selftest/hand-*.png`；
- 主链路自检新增一条**几何级**断言："手/小臂已烘焙暖色明暗（不再是纯白板）"（不依赖截图姿势/背景）；
- 单测 `skin-shading.test.ts` 6 条：只写手部、InterleavedBufferAttribute 转换、归一化 Uint8 转换、幂等、明暗公式边界、普通 Mesh 不被误伤。

### D6 资产事实与换模型注意事项

- 本资产的身体贴图是平涂色块；手部 UV 极小、颜色 `#f1edec`；
- **换模型/换皮肤后必须重跑 `PET_HAND_DIAG=1`**：若新模型手部贴图本身有明暗，`tint` 会把它整体压暗、`COLOR_0` 烘焙会叠加一层固定光向；届时把 `DEFAULT_SKIN_SHADING` 调成 `tint=(1,1,1)`、`diffuse=0` 或关闭烘焙；
- 不要把本 ADR 的"手部 UV 位置/颜色/顶点数"当成通用规则，它们只描述 `CH0335.glb`。
