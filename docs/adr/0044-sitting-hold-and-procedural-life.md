# 0044. 坐姿回到停帧 + 全程序化微动（呼吸 / 自主张望 / 眨眼 / 悬空晃腿）

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-11-04 |
| 决策者 | 项目所有者（真机反馈：0.42s 循环像"抽搐"，要活感） |
| 关联 | 契约 §4.1（`idle` / `sitting`）、§5.2、§7.3（render 表现规则）、§11、§12；ADR 0014（骨骼仲裁）、ADR 0026 D7（眨眼是骨骼动画）、ADR 0028 D8（坐姿）、ADR 0043（循环坐姿与补偿插值 —— **D2 被本 ADR 废止**） |

## 背景

上一轮（ADR 0043 D2）为了"别像假人"，把坐姿片段裁成 0.42s 并**循环**播放。真机反馈很明确：

> 上一轮的 0.42s 循环导致坐姿像在"抽搐"，彻底废弃。

目标画面（用户原话）：**安静地坐在窗沿上，身体有平缓呼吸，偶尔眨眼，并且会自己左右张望（不再死盯光标），双腿轻微交替悬空晃动。**

## 排查

### 1. 循环为什么读作"抽搐"

0.42s 循环 = 每秒换 2.4 次姿态，接缝 1–2px 虽然看不出来，但**节奏本身**已经接近"抖动"；
再叠上每帧都在走的呼吸，整体就像一个被快进的小循环。停帧则完全没有节奏——但会像假人。
结论：**姿态要静（停帧），运动要自己造（慢变量）**，不能靠"快速循环片段"制造动感。

### 2. 停帧之后哪些东西停了

`playHold`（`LoopOnce` + `clampWhenFinished`）把片段钉在最后一帧：呼吸（胸腔/肩）、头发、
布料、**眨眼**（`bone_eye_D_*` 的平移）全部冻结。所以四件事都要程序化重建。

### 3. 顺带挖出一个真 bug：`roleWeight` 把"暂停"当"没在播"

`clampWhenFinished` 会把 action 置为 `paused = true`，此时 `isRunning()` 返回 **false**。
ADR 0043 的 `roleWeight()` 用它过滤，于是坐姿停帧 0.42s 后权重从 1 掉到 0 →
**整块身体平移补偿消失**：自检截图里她被推到窗口左边、只剩半个身子（`window-sitting.png` 可复现）。
修法：animation-controller 维护一张"已激活角色表"，`roleWeight` 只看激活 + `enabled` + 权重。

### 4. 眨眼的真实幅度：平移要够大，且基线帧必须"睁眼"

- 资产里眨眼 = `bone_eye_D_L/R.translation.x`（`Cafe_Idle` 2.5s：0.000262 → 0.000451，Δ≈0.00019）；
- 之前坐姿窗口停在 14.92s，那一帧眼皮 x 已经是 0.000314（**半闭**），叠加 Δ 后"看不出闭眼"；
- 试过再叠 `_01/_02` 的 0.35rad 旋转（世界 X 轴、两个符号都试），对虹膜覆盖**零贡献**——
  世界轴旋转对这些子骨近似"自转"，只会让眼皮贴片打转。**不做**；
- 只放大平移：Δ = 0.00017 时虹膜覆盖 3.4% → 1.4%（**60%**，半闭）；Δ = 0.00028 时 2.8% → 0.26%（**91%**，真闭眼）。

### 5. 晃腿不能"往下摆"

坐姿把**身体最低点钉在窗口底边**（`sitOffsetPx`），靴底正好贴着窗口下沿。
纯正弦的负半周会把脚甩出窗口（被裁掉）——违反"微动不能破坏吸附锚点"。

## 决策

### D1 坐姿回到停帧，窗口取"最平稳且睁眼"的 14.5–14.7s

`clip-bank.sit`：`loop: false`、`startSeconds 14.5`、`maxSeconds 14.7`；`enterSit` 用
`playHold('sit', 0.45)`。为什么是 14.7 而不是 14.92：
14.5→14.7 的骨骼差（头 y 0.0003 / 骨盆 0.0002 / 脚底 0.0005）同样稳定，但 14.8s 之后她开始**眯眼**
（14.92s 眼皮 x 已到 0.000314），基线半闭会让程序化眨眼看不出来。

停帧之后 Mixer 只提供**静态姿态**（three 的 `PropertyMixer` 还会跳过冗余写入）；
所有"变化"都由下文的程序化层给出。

### D2 呼吸：一根 3.6s 正弦，整体浮动 ≤1px + 脊柱微旋

| 量 | 参数 | 说明 |
|---|---|---|
| 整体高低 | `SIT_BREATH_FLOAT_PX = 0.9` | **≤1px**（旧版 2.4px + 0.5% 躯干缩放 = "心跳感"，已删） |
| 脊柱 | `SIT_BREATH_SPINE_RAD = 0.006` | 胸腔起伏 |
| 脊柱 1 | `SIT_BREATH_SPINE1_RAD = 0.004` | 同相、幅度递减 |
| 颈 | `SIT_BREATH_NECK_RAD = -0.0025` | 轻微反向，像"抬头呼吸" |
| 周期 | `SIT_BREATH_PERIOD_MS = 3600` | 3–4s，低于 2.5s 会读成"喘" |

**不再用根节点 `scale.y` 做呼吸**：缩放会把头发/衣服一起放大，读起来像心跳（ADR 0043 D4 的旧做法废止）。

### D3 自主张望：坐姿期间关闭光标视线

- `render-module` 的视线通道：`sitMotionOn = sitPoseActive && sitGain > 0.01` → 坐姿时**不调用**
  `gaze.update()`；光标视线控制器保持原值（不再被光标带走）。
- 新的调度器在 `sit-motion.ts`：维持当前方向 `SIT_GAZE_HOLD_MIN/MAX_MS = 3000/6000`，
  然后随机一个目标（`SIT_GAZE_YAW_RAD = 0.3`、`SIT_GAZE_PITCH_RAD = 0.15`），
  以 `alpha = 1 - exp(-3.2·dt)` 的阻尼缓动过去（**永不瞬移**）；
  头部走 arbiter 的 yaw/pitch，眼球再加 `SIT_GAZE_EYE_EXTRA = 0.35` 倍。

### D4 眨眼：2.5–5s 一次，眼皮平移 + 平滑包络

- 排期：`SIT_BLINK_MIN/MAX_INTERVAL_MS = 2500/5000`；
- 包络：闭合 110ms（smoothstep）→ 保持 50ms → 睁开 180ms（合计 340ms，接近官方那一下）；
- 幅度：`SIT_BLINK_TRANSLATION_X = 0.00028`（模型单位，沿眼皮骨本地 x；两眼皮同号同幅）。
  这是**实机标定值**：0.00017 只闭 60%，0.00028 闭 91%（判据 = 眼部 ROI 的虹膜像素占比，
  `tools/measure-blink.py`）。
- 实现：`bone_arbiter` 新增 `addPosition()` —— 位置偏移与旋转用**同一套"检测 mixer 是否重写"** 的逻辑
  （`capture()` 前后比 `bone.position`）。停帧时 three 同样会跳过位置的冗余写入，不做这一步
  眨眼位移会逐帧累积（越眨越大）。

### D5 悬空晃腿：只往"抬"的方向摆，左右交替

```
liftL = 0.5 - 0.5·cos(ωt)            // 0→1→0，单峰
liftR = 0.5 - 0.5·cos(ωt + π)        // 反相，左右交替
thigh = -SIT_LEG_THIGH_RAD · lift    // 负 pitch = 腿前抬（ADR 0035 D5 标定）
calf  = +SIT_LEG_CALF_RAD  · lift    // 正 pitch = 小腿后折（膝盖弯，脚往回收）
ω = SIT_LEG_SWING_RAD_PER_SEC = 2
```

- 为什么不是纯 `sin`：负半周会把脚甩到窗口外（见排查 5）。这样**任何时刻都不低于静止姿态**，
  视觉上就是"左脚抬一下、右脚抬一下"。
- 幅度：大腿 ±0.08rad、小腿 0.06rad；包络 `SIT_LEG_RAMP_MS = 600`（软启动，不"啪"地开始晃）；
  整套微动还有一层 `SIT_MOTION_RAMP_MS = 500` 的总包络（落座淡入 / 解除淡出）。

### D6 与锚点/补偿的关系、可观测与取证

- **补偿只跟 `sitGain`**（ADR 0043 D3），微动只走 `applySitMotion()`：两者**相加**而不是相乘，
  所以 ±0.9px 的呼吸永远不会被放大到 ±265px 的补偿上；窗口位置完全不受影响（仍由 shell 定）。
- 所有参数集中在 `shared/constants.ts` 的「坐姿活体微动」段（用户硬约束）。
- 诊断：`RenderDiagnostics.sit.motion`（`gain/breathPx/gaze/blink/legs`）。
- 取证接口（内部，不进 `RenderState`）：
  - `sitMotionDiagnostics()`：**极轻**的微动快照（`getDiagnostics()` 单次约 300ms，
    眨眼只有 340ms，采不到峰值）；
  - `debugBlink(holdMs)`：立刻眨眼；`holdMs > 0` 钉在闭眼、`< 0` 钉在睁眼（只用于截对照图）。

## 替代方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 保留 0.42s 循环 + 减振幅 | 改动最小 | 用户明确否决"抽搐"；循环节奏本身就是问题 | 否 |
| 停帧 + 只加呼吸 | 最省事 | 没有张望/眨眼/晃腿，仍然是"活着的假人" | 否 |
| 眨眼叠 `_01/_02` 的旋转 | 更接近官方 | 世界轴旋转对子骨近似自转，实测零贡献 | 否（只放大平移） |
| 晃腿用纯正弦 | 公式最直观 | 脚会甩出窗口（违反锚点约束） | 否（改单峰抬腿） |
| 坐姿仍跟随光标（旧行为） | 少写一个调度器 | 用户明确要求"不再死盯光标" | 否 |
| **停帧 + 全程序化微动（本方案）** | 节奏可控、参数集中、零新状态 | 呼吸/张望/眨眼/晃腿全是手写的，需要按资产标定 | **是** |

## 后果

**正面**

- 坐姿不再抽搐：姿态完全静止，只有 3.6s 的呼吸、3–6s 的张望、2.5–5s 的眨眼、2rad/s 的交替晃腿。
- 眨眼是真闭眼（虹膜覆盖 2.8% → 0.26%），且不靠贴图/差分资源。
- 坐姿期间光标不再控制视线；离开坐姿后光标视线照旧。
- 顺带修掉 `roleWeight` 的"暂停 = 没播"bug（否则补偿会整块消失、人被推到窗口外）。
- 新增 10 个单测（呼吸曲线 / 眨眼包络 / 晃腿有界与交替 / 调度器软启动与退场 / 张望边界与缓动 /
  眨眼排期 / `roleWeight` 停帧与未播放）+ 主链路 6 条自检。

**负面 / 成本**

- 微动的观感全靠参数：呼吸 0.9px 是"刚好能看出"的下限，再小就回到"假人"。
- 眨眼幅度 0.00028 比资产自带的 0.00019 大 ~47%，是"为了看清"做的艺术放大；换模型要重标。
- 晃腿只在"抬"的方向摆，严格说不是钟摆；这是锚点约束下的取舍。
- `getDiagnostics()` 太重（~300ms），取证必须另开轻量接口；这是一条长期成本。

**约束**

- 坐姿片段必须**停帧**（`playHold`），不得再循环；运动只能来自 `sit-motion`。
- 微动不得改变窗口位置、不得改 `RenderState`、不得新增状态/事件/IPC。
- 所有幅度/周期只写在 `shared/constants.ts`；`sit-pose.ts` 只负责 240ms 的坐下过渡与降级姿态。
- 眨眼幅度/方向必须用 `tools/measure-blink.py` 复核（虹膜覆盖 ≥90% 才算"闭上"）。
