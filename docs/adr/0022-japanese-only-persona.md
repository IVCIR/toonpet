# 0022. 全切日文：角色只用日文回复（提示词 / 角色卡 / 台词池 / 校验器 / TTS 语种）

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-30 |
| 决策者 | 项目所有者 |
| 关联 | `CONTRACTS.md` §9.2、§9.3 段 1/2、§7.4；ADR 0019（TTS 语种配置，本 ADR 修订它的 `text_lang` 默认值）；ADR 0020（memory）；ADR 0021（字幕时序）；ADR 0018 D2（输出清洗） |

## 背景

角色卡、台词池、提示词、TTS 语种在上一轮都是"日文参考音频 + 中文回复"的组合：

| 位置 | 上一轮状态 |
|---|---|
| `data/character-card.md` | 中文人格描述 + 中文 few-shot 示例 |
| `data/lines.json` | 7 条规则 + 5 条兜底的 `reply.text` 全是中文 |
| `prompt.ts` 段 1 | `text：1–120 个字符，单段中文…` |
| `TTS_TEXT_LANG`（`constants.ts`） | `'zh'`（ADR 0019 D1） |
| `.env` | `PET_TTS_TEXT_LANG=zh` |

本轮要求"全切日文人设"：**无论用户用什么语言提问，角色都只用纯正日文回答**。验收标准第一条就是"输入『你好』，桌宠用全日文回答"。

这里有一个容易漏掉的事实：`你好` 会命中台词池的 `greet` 规则（`route=rule`），**根本走不到 LLM**。所以只改提示词是不够的——台词池不说日文，验收就必然失败。同理，兜底台词在 LLM 不可用时是唯一输出，也必须是日文。

## 决策

### D1 台词池 `data/lines.json` 全量日文化，关键词保留中文并补日文

- 7 条规则与 5 条兜底的 `reply.text` 全部改为日文（敬体为主，保留 `……`、`「」` 等口癖标点）。
- `match.keywords` **保留原有中文词**并**追加日文说法**（`おはよう` / `こんにちは` / `ゲーム` / `開発部` / `ご飯` / `アリス` …）。理由：用户可能用中文提问（输入通道不受语言限制），只留日文关键词会让中文输入全部掉到 LLM 路径，既慢又贵（本机 1.7–2.6s）。
- 关键词仍然"短而具体"：上一轮实测过 `测试` 这种宽词会误伤自检样本；本轮同样避免加入 `好き`（会把"コーヒーが好き"这类普通陈述误判成"夸奖"规则）。

### D2 角色卡：把语言约束放在文件最前，few-shot 改成"中文问、日文答"

`data/character-card.md` 新增第一节 **语言（最高优先级，先于以下所有内容）**：

```text
- 你必须完全使用纯正日文进行回复，不要使用中文（简体或繁体都不要）。
- 用户可能用中文提问，你仍然只用日文回答…
```

并把 3+1 组 few-shot 的凯伊台词改成日文（用户台词保持中文），最后补一组 `用户：你好 → 凯伊：……先生、おはようございます。…`——这正是验收样本，让模型有直接可模仿的对象。

**为什么放最前 + 重复两遍**：`qwen3:4b` 这种小模型对 system 段**开头与结尾**的指令最敏感，中间的人格描述会稀释语言约束。段 1（`prompt.ts`）也写了同一条（D3），形成两层防线。

### D3 提示词段 1 增加"语言硬约束"，并把 `text` 的语言写明日文

```diff
- 'text：1–120 个字符，单段中文，不含 Markdown、URL、代码块、括号动作描写，不要换行。',
+ '【语言硬约束】text 必须完全使用纯正日文（日本語）书写：禁止出现中文（简体或繁体）、韩文与英文句子。即使用户用中文提问，也只能用日文回答。',
+ 'text：1–120 个字符，单段日文，不含 Markdown、URL、代码块、括号动作描写，不要换行。',
```

### D4 校验器：**不**强制语言，只修掉两处会误判日文的地方

`reply-validator.ts` 的职责是结构/枚举/长度/装饰，不是内容策略：

| 改动 | 理由 |
|---|---|
| 新增 `joinCjkWithoutSpace()`：去掉**两个中日文字符之间**的半角空格 | 模型在句子中间换行时，旧的 `\s+ → ' '` 会产出 `はい わかりました` 这种非自然空格（日文不用空格），TTS 会读成突兀停顿，字幕也难看。ASCII 与 CJK 之间（`OK 了解`）**保留**空格 |
| `FORBIDDEN_CHARS` → `FORBIDDEN_MARKUP` 并加注"日文标点允许" | 原名暗示"字符黑名单"，容易被后人误以为要拦 `、。！？…「」『』・〜ー`。这些是正常日文标点，**必须放行**；真正要拦的是 Markdown 与括号动作描写 |
| **不加**"必须含假名"的硬判定 | 会把 `Ｋｅｉ`、纯数字、专有名词回复打成 `invalid_output`，让兜底台词顶掉合法回答——这正是"误判"。语言是内容策略，由提示词与台词池保证 |

日文相关的其余行为本来就是对的，本轮只是**用测试锁住**：长度按码点计（`[...text].length`）、`「」` 与全角标点放行、全角括号动作 `（小声で）` 走清洗而不是直接判非法、URL/Markdown 仍严格拒绝。

### D5 TTS 语种默认值：`TTS_TEXT_LANG = 'ja'`（修订 ADR 0019 D1）

- 角色只说日文 → 合成文本语种与参考音频语种一致，本机默认就是 `prompt_lang=ja` + `text_lang=ja`。
- `.env` 仍显式写 `PET_TTS_TEXT_LANG=ja`（显式优于隐式，也方便临时改回中文做对照）。
- ADR 0019 D1 的"`text_lang` 默认 zh"由本 ADR 修订（ADR 只增不改）。代码默认值改动的好处：**没有 `.env` 的机器也是对的**，不会出现"新克隆仓库用日文人设却合成中文"的错配。

### D6 自检桩同步日文化

`selftest-stubs.ts` 的默认 LLM 回复改为日文（`先生、私はここにいます。今日もよろしくお願いします。`），否则 `selftest:speech` 的"字幕文本"断言仍在验证中文形态，与产品形态脱节。`INVALID` / `NOAUDIO` / `SLOWTTS` / `第一句` / `第二句` 这些**测试标记**保持原样（它们是协议，不是台词）。

## 替代方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 只改提示词，台词池保持中文（本方案否） | 改动最小 | `你好` 命中规则 → 说中文 → **验收直接失败** | 否 |
| 只把台词池翻译成日文，关键词也只留日文 | 数据更一致 | 中文输入全部落到 LLM（慢、依赖本地模型），且本机冷启动首问可能撞 8s 预算 | 否 |
| 在 `reply-validator` 里硬性要求"必须含假名" | 看起来"强制日文" | 误杀专有名词/纯拉丁回复；把内容策略塞进结构校验，降级率上升 | 否 |
| 用 `all_ja` 作为 TTS 语种 | 更"强制" | `all_*` 面向整段纯语言文本；回复里出现数字/英文名时反而受限（ADR 0019 已解释） | 否 |
| 保留 `text_lang` 默认 zh，只靠 `.env` | 不动常量 | 新机器/无 `.env` 时默认错配，最隐蔽的一类故障 | 否 |
| 让 LLM 用中文思考再翻译成日文 | 语义可能更准 | 多一次推理（计费与延迟都翻倍），且违反"零成本/低延迟"取舍 | 否 |

## 后果

**正面**

- 验收样本 `你好` 在**规则路径**就返回日文，不依赖 LLM 是否在线。
- 三层语言约束（角色卡开头 / 提示词段 1 / 台词池）互相兜底；LLM 不可用时兜底台词也是日文。
- TTS 语种与文本语种一致（`ja`/`ja`），省掉跨语种转换的不确定性。
- 校验器对日文标点、码点长度、换行拼接都有单测（新增 7 条），"不误判"变成可执行断言。
- 日文句子普遍比中文长，配合 ADR 0021 的"字幕跟随语音"才不至于出现"字没了声音还在"。

**负面 / 成本**

- 台词池的润色质量直接决定第一印象；本轮是"通顺且符合人设"，不是"母语级润色"，后续可逐条打磨。
- 中文关键词与日文关键词并存，规则池变长（每条约 8 个词）；过宽的关键词会误伤（上一轮已踩过），需保持"短而具体"。
- 用户用中文提问、角色只答日文，会有"听不懂"的观感；这是产品选择，不是缺陷。
- 校验器不做语言校验，意味着**模型偶尔仍可能蹦出中文**（提示词只是降概率）。若真发生，日志里能看到原文，属于内容问题而非校验问题。

**约束**

- 不得在 `reply-validator` 里新增语言硬判定（会误杀合法回复）；语言由提示词/角色卡/台词池保证。
- 台词池 `reply.text` 必须过 §9.2 的严格校验（已有装配期断言），新增日文台词要先跑 `npm test`。
- `TTS_TEXT_LANG` 默认值与角色语言必须一致；换语言时三处（常量、`.env`、角色卡）一起改。
- 中日文之间不得插入半角空格（`joinCjkWithoutSpace` 是唯一实现点）。
