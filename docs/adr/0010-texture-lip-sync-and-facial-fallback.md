# 0010. 贴图式口型与表情降级（无 blendshape、无眼睑）

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-28 |
| 决策者 | 项目所有者 |
| 关联 | `CONTRACTS.md` §3.1（voice/render 口型通道）、§4.5（emotion）、§5.2/§5.3（口型通道优先级）、§7.3、§11（表情缺失）；ADR 0009 |

## 背景

`CH0335.glb` 的资产盘点结论（上一轮实测，本轮不再重复探查）：

1. **没有任何 morph target（blendshape）**：5 个网格的 primitive 全部 `targets` 为空。§5.2 的"口型通道由包络驱动 blendshape"在 v1 上没有实现载体。
2. **没有眼睑骨骼**：骨骼表里只有 `Bip001 eye_L / eye_R`、`bone_eye_D_*`（眼球方向）、`bone_Eyering_*`（虹膜环）、`Xtra_eyeblow*`（眉毛），没有 `eyelid` / `eye_close` 一类可用于闭眼的骨。
3. **"压扁眼球做眨眼"已被证伪**：对 `Bip001 eye_L/R` 施加 `scaleY` 后，高光与瞳孔一起变形，截图明显不是眨眼。v1 不实现眨眼。
4. **口型只能走贴图**：模型自带 `CH0335_EyeMouth` 材质（baseColorTexture = `CH0335_EyeMouth.png`，眼睛与嘴共用一张图）。外部已有嘴型图集 `Character_Mouth_Black-Due3Gpre.png`，可在运行时把嘴型画进这张贴图再交给材质。
5. 44 段动画里没有可用于表情/口型的 morph 通道；它们都是骨骼动画（CM3D2/BA 风格），与口型无关。

契约 §5.2 把口型通道定为最高优先级、且"任何情况下不被覆盖"；§11 要求"表情缺失 → 表情不生效，动作正常，记录一次告警"。本轮没有语音驱动，但需要把"以后怎么实现"钉死，避免阶段 5 再发明一套。

## 决策

### D1 v1 的"面部降级"：不眨眼，改视线微动

1. v1 **不实现眨眼**，也不为它保留开关；`RenderState` 里没有任何眨眼字段。
2. 无光标/长时间无交互时，用**视线微动**替代眨眼：每 5 s 随机一个视线偏移（yaw ±0.20 rad、pitch ±0.10 rad 内），叠加在头部/眼骨的平滑跟随之上，周期与幅度进共享常量。
3. 视线跟随与微动都只写 `Bip001 Head` / `Bip001 eye_L/R` 的旋转，**不写缩放**（避免重演 scaleY 的变形问题）。
4. 关键骨骼（`head` / `eyeL` / `eyeR`）缺失时按 ADR 0009 D6 **整体回退**成占位胶囊体（§7.3），而不是"只关视线"；`Pelvis` 缺失只影响自检点位，不影响显示。

### D2 口型：外部图集 → 画进 `EyeMouth` 贴图（贴图切换式）

1. 载体是模型自带的 `CH0335_EyeMouth` 材质（`baseColorTexture = CH0335_EyeMouth.png`）。贴图同时含眼睛与嘴，所以**不能整张替换**，否则眼睛被图集覆盖。
2. 实现方式是"合成"：以原 `EyeMouth` 贴图为底，用 2D canvas 把外部图集里的嘴型区域画到嘴的位置，生成 `CanvasTexture` 覆给材质；`setFrame` 只重画嘴部矩形并 `needsUpdate = true`，不重建整张贴图。
3. 图集按网格切分：`Character_Mouth_Black-Due3Gpre.png`（1024×1024、8×8 帧、透明底）的嘴型帧用**网格行列 + 单帧 UV 矩形**描述，参数（列数、行数、嘴锚点矩形、缩放）进共享常量/配置，不写死在渲染循环里。
4. 阶段 5 的驱动源是 `voice` 的 PCM RMS 包络（§5.2 口型通道），本轮**不接线**；本轮只提供接口与一条"能画出第 N 帧"的路径。
5. **v1 会画一张静态底图**（落地时补的决策）：资产里 `EyeMouth` 网格含一块**纯白嘴部底板**（UV `0.0089..0.2411 × 0.7926..0.9571`，从 UV 岛 + 贴图采样实测），游戏里由 shader 绘制；不处理时脸上是一块白矩形（实测截图）。因此 v1 把底板刷成 `Face` 贴图采样出的肤色，并画上图集第 0 帧（静态闭嘴）。这**不是口型驱动**：没有任何包络/事件输入，只是让脸可看；阶段 5 只替换"驱动源"。
6. 合成用 **8× 超采样 CanvasTexture**（EyeMouth 原图 128²，嘴部底板仅约 30×21 texel；直接画会被线性过滤糊掉），每帧只重绘这块 canvas 并 `needsUpdate = true`。
7. 接口（内部，不跨进程、不属于 §7.3）：
   ```ts
   interface MouthChannel {
     readonly materialName: string | null;
     setFrame(index: number, frameCount: number): void; // 0 = 闭嘴
     reset(): void;                                     // 回到原始贴图
     dispose(): void;
   }
   ```
8. 材质/贴图缺失 → 记一次 WARN，`materialName = null`，`setFrame/reset` 全部变空操作；不得抛异常、不得阻断模型显示（§11）。

### D3 表情：只保留状态，不伪装成 blendshape 驱动

1. `emotion` 仍是契约 §4.5 的状态字段，由 `intent_resolved` 携带；v1 **没有**视觉表情映射（无 blendshape、无眼睑），不新增也不改写任何 emotion 值。
2. 视觉表情的唯一可行路径同样是贴图（眼睛/眉毛/嘴都在 `EyeMouth`/`Face` 贴图上），归属阶段 5 与 D2 同一套合成管线；本轮不实现。
3. `render` 不得因为"没有表情载体"就把 `emotion` 从状态里抹掉或造假；`getState().emotion` 继续如实反映当前情绪状态。

## 替代方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 用 eyeball `scaleY` 模拟眨眼 | 零资产改动 | 已实测：高光/瞳孔变形，完全不像眨眼 | 否（已证伪） |
| 加自定义 blendshape 到 GLB | 最正确 | 需要改资产并与外部图集脱节；用户明确 v1 不做 | 否 |
| 用眼睑骨骼驱动 | 最自然 | 模型没有眼睑骨；新增骨骼等于重做模型 | 否 |
| 用外部图集**整体替换** `EyeMouth` 贴图 | 实现最简单 | 眼睛会被嘴型图集覆盖（图集只有嘴） | 否 |
| 图集合成到原贴图的嘴部区域（本方案 D2） | 保留原眼睛、嘴可逐帧切换、无 blendshape | 需要一张 canvas 与嘴锚点参数；每帧上传一次小区域 | **是** |
| 用 CSS/叠加面片做嘴 | 不动材质 | 需要额外几何与遮挡处理，和蒙皮绑定困难 | 否 |
| 口型由独立小 plane 贴在脸上 | 无贴图重绘 | 蒙皮跟随、透明度排序、深度冲突都要自己处理 | 否 |
| 直接按包络改材质颜色/透明 | 零贴图 | 嘴型不是颜色能表达的 | 否 |

## 后果

**正面**

- 阶段 5 的落地路径唯一且已经验证过资产结构（`EyeMouth` 材质存在、图集已就位），不会再为"为什么没有 blendshape"返工。
- 不眨眼是**明确决策**而不是遗漏；视线微动让 v1 仍有活物感。
- 面部降级与 §11 的"表情缺失"一致，不新增状态、不新增事件、不改 `RenderState`。

**负面 / 成本**

- v1 视觉上"没有眨眼"，近距离观察会觉得眼睛偏静态；只能靠视线微动弥补。
- 贴图式口型每帧要重绘嘴部矩形并上传纹理，阶段 5 需要控制帧率（预计 ≤30 Hz）。
- 图集帧的锚点/缩放参数是资产相关的，换图集要改配置。

**约束**

- 不得用 `scaleY`/骨骼缩放实现眨眼或表情（已证伪）。
- 不得整体替换 `EyeMouth` 贴图（会覆盖眼睛）；必须先合成再使用。
- 不得新增 emotion/intent 值；表情视觉只允许走 D2 的贴图管线。
- `MouthChannel` 只允许由渲染侧内部持有，不跨进程、不进 `RenderState`。
- 本轮不得把 `voice` / 口型驱动接进来（阶段 5 才做）；接口可空转，但不得被任何事件驱动。
