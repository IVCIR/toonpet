## 背景

当前拖拽是“整体平移 + 统一摇摆 + 松手弹簧”：

- 窗口位移 = 按下点 + 光标累计位移（`drag-gesture.ts` 的 `moveWindowTo`），模型与光标刚性绑定；
- `dragged` 期间只叠 `±0.05rad / 1.6s` 正弦与 18px 抬升（`render-module.ts` 的 `DRAG_SWAY_*`），与鼠标动作无关；
- 松手由 shell 弹簧拉回地面线，render 只做 `180ms / 6%` 的 `scale.y` 压扁。

用户要求：

1. 把“鼠标点在模型的哪个部位（头/手/身体/脚）”变成可见的悬挂差异；
2. 悬挂要像钟摆：按鼠标移动的加速度与抓取点相对位置计算受迫摆动，松手后惯性自然衰减；
3. 落地要按冲击分级做下蹲缓冲，不能硬弹；
4. **不引入 Pymunk / Cannon-es 等物理引擎**，只用数学与现有骨骼；
5. 不新增状态、不改 `RenderState`、不新增 IPC 通道。

## 决策

### D1 抓取点的事实留在渲染进程（不改契约、不新增 IPC）

`cmd:drag` 只承载原始指针事实（`{phase,x,y,t}`，契约 §3.5），且 ADR 0004 D2 明确“禁止在这里加字段”。本轮**不扩 `cmd:drag`、不新增通道**，原因是抓取点本来就在渲染侧：

- `pointerdown` 发生在渲染页，`clientX/clientY` 先在渲染侧拿到；
- 掩膜 `bbox`、骨骼世界坐标也都在渲染侧；
- 主进程只需要光标位移来移动窗口，不需要知道抓了哪里。

补充事实：`drag_started` 载荷里的 `{x,y}` 是“越过 4px 阈值时的光标点”，不是按下点（`drag-gesture.ts` 的 `tick()`），用它反推抓取点会偏 4px 以上。因此渲染侧在 `pointerdown` 时记录“待定抓取事实”，在 `drag_started` 到达时消费。

**分类规则**（按优先级）：

1. 骨骼相对位置：头骨、骨盆、左右脚骨投影到内容区 CSS 坐标，取最近部位；头骨附近但低于肩线 → 头；脚骨附近且低于膝线 → 脚；其余 → 身体；
2. 骨骼缺失时退回掩膜 `bbox` 三段带：顶部 `HEAD_BAND_RATIO`（22%）= 头，底部 20% = 脚，其余 = 身体；
3. 掩膜也不可用（cold/stale）时退回“身体”，并记一条诊断。

### D2 绕抓取点旋转，而不是绕脚底旋转

`animationRoot` 的原点是内容区底边中心。直接改 `rotation.z` 是绕脚底转，抓头时会变成“脚在原地、头画大弧”。用二维刚体变换绕支点：

```
B = 当前基础偏移（lift / sit / hop / 反应位移）
p = 抓取点在 animationRoot 局部坐标中的位置（由真实按下点换算）
R(θ) = 二维旋转矩阵
animationRoot.position = B + p - R(θ)·p
animationRoot.rotation.z = θ
```

这样抓取点保持不动，身体绕它摆；不新增场景节点，不改变地面校正、坐姿补偿与光环跟随。

**支点用真实按下点，不用骨骼中心**：按下点已经通过掩膜命中（alpha ≥ 0.5），就是"手抓住的那个像素"；用骨骼中心会让抓头发时支点跑到头部中心（实测差 140px），看起来像"站在光标旁边"。骨骼只用于分类（head/body/foot），不用于支点定位。

### D3 受迫单摆（纯数学，无物理引擎）

以抓取点为支点、有效摆长 `L`，在加速参考系中：

```
θ̈ = -(g_eff / L)·sinθ - c·θ̇ - (a_x / L)·cosθ
g_eff = clamp(g + a_y, 0.35g, 2.2g)
```

- `a_x, a_y` 是**窗口支撑点**的加速度：渲染侧每帧读 `window.screenX/screenY`，两级 EMA + 死区 + 限幅；不跨进程。
- 积分：半隐式欧拉 + 4ms 固定子步长（与 `shared/motion.ts` 的 `stepSpring` 同一手法）；`dt` 上限 50ms。
- 限幅：头/身 `|θ| <= 0.35rad`、脚 `|θ| <= 0.25rad`；`|ω| <= 6rad/s`；所有输入先过 `Number.isFinite`。
- 抓脚额外叠 `2.5Hz` 小幅挣扎振荡 + 每 0.8–1.4s 一次踢腿包络（纯正弦/包络，不引入随机状态到状态机）。
- “抓头 L 大、阻尼略大；抓脚 L 小、阻尼极小”作为初始值，全部放 `shared/constants.ts`，支持后续调参。

### D4 松手惯性与分级落地

- `drag_released` 不重置 `θ/ω`；停止外力后继续用 `settling` 期间的支撑加速度驱动，姿态增益 0.4s 淡出；
- `motion_ended{settle}` 时用 `settling` 期间记录的向下峰值速度 `vDownMax` 计算冲击：
  `impact = clamp((vDownMax - 150) / 1000, 0, 1)`；
- 下蹲包络 0–300ms：0–50ms 吸震、50–150ms 轻微回弹、150–300ms 回正；
- **以 `animationRoot.scale.y` 为主**（脚底不动，不会穿出窗口底边），脊柱/颈/手臂骨骼偏移为辅；膝盖弯曲幅度 ≤0.18rad，若实机出现脚离地/穿出窗口，就把膝盖曲度降到 0，全靠 `scale.y`。
- 不使用 IK；不做逐帧包围盒重算。

### D5 骨骼轴向：世界轴仲裁 + 调试 API + 标定后才写符号

3ds Max 导出的 Bip001 局部轴不可信，但现有 `BoneArbiter.add(bone, yaw, pitch, roll)` 已经把世界轴转换到父空间再叠加，因此：

- `pitch` 永远是绕世界 X 轴（低头/抬头）；
- `roll` 永远是绕世界 Z 轴（左右倾/抬手）；
- `yaw` 永远是绕世界 Y 轴（左右转）。

即便如此，**符号仍取决于模型朝向与左右侧**。本轮要求：

1. 先提供 `window.diagnostics` 调试 API：`listBones()`、`setBoneOffset(name, yaw, pitch, roll)`、`clearBoneOffsets()`；可按单根骨骼施加正/负偏移；
2. 通过截图确认 `spine` / `neck` / `upperArmL` / `upperArmR` 的“低头/抬头、抬手/放手”符号；
3. 确认后把符号写进 `drag-motion.ts`，并加注释（例如 `// spine.pitch = +0.2 表示低头（实机截图确认）`）；
4. 标定截图与结论写入 `MODULE_STATUS.md` 的“已知坑位”。

### D6 落地冲击的分级标定

必须分别测试：

1. 从 10px 高处松手（轻放）；
2. 从 300px 高处松手（重摔）。

对比截图：重摔时 `scale.y` 的压扁幅度与脊柱前倾明显更大，且脚底没有穿出窗口底边。若穿帮，按 D4 的降级顺序把膝盖曲度降到 0。

### D7 常量、诊断与契约

- 所有参数集中在 `src/shared/constants.ts`：摆长、阻尼、重力、角度上限、挣扎频率/幅度、落地包络、抓取带比例、接近速度/时长。
- 诊断新增内部 `drag` 块（`band`、`pivot`、`angle`、`omega`、`supportAccel`、`phase`、`landingImpact`），不进 `RenderState`。
- **不改契约**：不新增事件、不新增状态、不新增 IPC 通道、不增删 `RenderState` 字段。

## 替代方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 扩 `cmd:drag` 加 `grabY/grabBand` | 主进程也知道抓取部位 | 违反 ADR 0004 D2“只承载原始指针事实”；需要契约 minor；IPC 往返只为分类 | 否 |
| 新增 `cmd:grab` / `cmd:drag-grab` 通道 | 语义独立 | 多一条通道；渲染侧本来就有事实 | 否 |
| 引入 Pymunk / Cannon-es | 物理真实 | 违反用户硬约束与 T-3；WASM/原生依赖 | 否 |
| 固定正弦 + 分部位不同相位 | 实现最省 | 仍与鼠标动作无关，治标不治本 | 否 |
| 真倒吊（绕脚转 180°） | 视觉冲击强 | 窗口 422×720 装不下，头会被裁掉；需动态窗口/锚点 | 否（改“挣扎”） |
| 膝盖大角度下蹲 + IK | 姿态更真实 | 无 IK，脚会离地/穿出窗口 | 否（以 `scale.y` 为主） |
| **渲染侧分类 + 支点旋转 + 受迫单摆 + 分级落地（本方案）** | 零依赖、零新通道、可单测、可诊断 | 需要标定骨骼符号；窗口量化噪声要滤波 | **是** |

## 后果

**正面**

- 抓头/抓身/抓脚有可辨识的悬挂差异；摆动由鼠标加速度驱动，松手保留惯性；
- 轻放/重摔的落地反馈不同，脚底不穿帮；
- 全部是纯函数 + 现有骨骼，零新依赖、零新定时器、零新 IPC；
- 物理与姿态都可单测，参数集中可调。

**负面 / 成本**

- 骨骼符号与幅度需要实机截图标定，不能凭感觉写；
- `window.screenX/Y` 有 1px 量化噪声，需要 EMA/死区，否则摆会抖；
- 抓脚的“挣扎”不是真倒吊，观感上限受窗口尺寸限制；
- 膝盖弯曲幅度受限，下蹲主要靠整体 `scale.y`，不如 IK 细腻。

**约束**

- 不得新增状态名、事件名、IPC 通道、`RenderState` 字段。
- 不得引入物理引擎；不得新增定时器；不得把抓取点传回主进程。
- 骨骼偏移必须通过 `BoneArbiter.add`，不得直接写 `bone.quaternion`。
- 落地时脚底不得穿出窗口底边；穿帮时优先牺牲膝盖曲度。
