# 0027. 编码事故复盘：禁止用 shell 文本往返改源码

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-11-01 |
| 决策者 | 项目所有者 |
| 关联 | ADR 0026（面部贴图/贴花）；本文件约束所有后续改动 |

## 事故

2026-10-31，为了让"眨眼"在截图里可见，执行了一次临时改行：

```powershell
(Get-Content src/renderer/render/render-module.ts -Raw) -replace '...', '...' |
  Set-Content src/renderer/render/render-module.ts -Encoding UTF8
```

PowerShell 5.1 的 `Get-Content` 默认按**系统 ANSI（GBK）**解码 UTF-8 文件：

1. 每个中文字符的 3 字节 UTF-8 序列被当成 1.5 个 GBK 字符 → 全文乱码；
2. GBK 双字节会把 `0x5C`（`\`）与部分换行当第二字节吃掉 → 字符串/模板字面量断裂；
3. 回写后文件 **305 个语法错误**，且编码反解不可逆（410 个字符落在 GBK 未定义区）。

**当时没有 git**，`build.mjs` 的 `rm -rf dist` 又清掉了上一份 sourcemap，全盘、编辑器历史、卷影副本均无备份 → 源码只能重写。

## 决策

### D1 禁止用 shell 做文本往返

- **不得**用 `Get-Content`/`Set-Content`/`-replace`/`sed`/`Out-File` 之类的管道改写源码文件。
- 改源码只用**结构化编辑工具**（读文件 → 精确替换 → 写回），它们按 UTF-8 处理且不做隐式转码。
- 需要批量改动时：写一次性脚本、**读 UTF-8 显式指定编码**（`-Encoding utf8NoBOM` / Python `encoding="utf-8"`），并先在副本上验证。

### D2 任何工程先建 git

- 新工程第一件事：`git init` + `.gitignore` + 首次提交，再写业务代码。
- 每个可运行状态提交一次；破坏性实验前先提交。
- 提交信息写清"改了什么、验证了什么"，便于回滚时判断。

### D3 破坏性实验走副本

- 为了截图/调试临时改常量时，改的是**副本或分支**，验证完立刻回滚；不在主工作区留临时改动。

### D4 构建产物不能当备份

- `build.mjs` 每次 `rm -rf dist`；`dist/*.map` 只在当次构建后存在。
- 因此 `dist` **不是**恢复源；恢复源只有 git 与显式备份。

## 后果

**正面**

- 事故后工程已建 git（`f653cd3` 事故基线、`8dc450a` 三轮重建），此后每次改动可回滚。
- 重写过程中 `tsc` 每轮清零、单测 272 全绿、自检恢复到 97/97，证明"小步 + 每轮验证"可行。

**负面 / 成本**

- `render-module.ts` 约 1400 行重写，消耗了三轮；部分细节（注释、日志措辞）与事故前不完全一致。
- 事故基线里保留着损坏文件，历史中会有一次"坏提交"（刻意保留，作为复盘证据）。

**约束**

- 改源码只用结构化编辑工具；shell 只用于读、构建、跑测试。
- 提交前必须 `tsc --noEmit` 通过；涉及渲染的改动必须跑 `npm run selftest`。
