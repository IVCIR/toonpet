## 背景

阶段 10 完成时，角色有动作（走路/拖拽/摸头/官方片段）与声音（本地 TTS + 包络口型），但有两个缺口：

1. **行走是"正面侧滑"**：`CH0335_Cafe_Walk` 是**正面**行走循环（实测截图确认），窗口按 `cmd:walk` 水平位移时角色仍面朝镜头，看起来像在冰面上平移。
2. **`emotion` 只有状态没有视觉**：`intent_resolved` 的 `emotion` 只进了 `getState()`，脸上只有嘴型随口型/摸头变化（ADR 0010 D3 明确写了"v1 没有视觉表情映射"，留给后续）。

本轮把这两件事一起做掉，并且**不引入任何按次计费调用、不新增状态/事件/`intent`/`emotion`、不改 `RenderState` 字段**。

## 资产事实（本轮实测，不再是猜测）

用只读脚本解析 `CH0335.glb` 的 POSITION / TEXCOORD_0 / 索引，按 UV 连通性分岛后得到：

| 材质 | UV 岛 | 顶点/三角形 | 面空间位置（模型单位） | 结论 |
|---|---|---|---|---|
| `Eyebrow` | `u 0.9551..0.9595 × v 0.0381..0.0459` | 156 顶点 | y −0.000997..−0.000884 | 眉/眼线是**1 texel 纯色块**，形状由几何体决定 |
| `Eyebrow2` | `u 0.3140..0.9282 × v 0.7498..0.9774` | 136 三角形 | y −0.000878..−0.000564，横跨双眼 | 虹膜环/眼线的一部分，与 `EyeMouth` 的虹膜岛**叠加**在同一片脸上 |
| `EyeMouth`（嘴底板） | `u 0.0089..0.2411 × v 0.7926..0.9571` | 32 三角形 | 平面（仿射拟合残差 1.1e-4） | 与既有 `plateUv` 常量完全一致，是**唯一可以自由画图案的平面** |
| `EyeMouth`（虹膜） | `u 0.2839..0.9575 × v 0.0376..0.9124` | 44 三角形 | y −0.000776..−0.000642，`x` 覆盖 ±0.000788 | 粉红漩涡虹膜画片；**左右眼共用同一块 UV** |
| `EyeMouth`（巩膜/眼睑条） | `u 0.14..0.16 × v 0.17..0.67` | 2 × ~90 三角形 | 与虹膜同高 | 2–3 texel 宽的竖条被拉伸覆盖整只眼：本质是**纯色** |

由此得到三条硬事实：

- **脸是曲面，UV→面空间不是仿射的**（逐岛拟合残差与岛自身尺度同量级），任何"按 UV 矩形贴图"的画法都会错位；
- **左右眼共用 UV**，所以眼型必须**镜像对称**（`>_<` 这种左右不同的画法在贴图上无法区分两只眼）；
- **眉毛/眼线的形状完全由几何体决定**，贴图只提供颜色 → §4.5 里"眉内侧下压""眉下压"两条**无法用贴图实现**。

## 决策

### D1 `walking` 朝向：走路时转向移动方向，停下回正

1. 偏航角目标由方向决定：右走 `+90°`、左走 `−90°`（three 的 +Y 旋转把 +Z 转向 +X，与"面朝镜头的 +Z"一致），停下/被拖拽/进入回弹时目标归 0。
2. 插值用**帧率无关的指数逼近**（`approach(current, target, dt, 9)`）≈ 0.3 s 走完 96%，不瞬切、不过冲。
3. 偏航写在 `animationRoot.rotation.y`，**与既有 `look` 反应（greet/look_at_user）相加**，两者共用同一个 Y 轴通道，不允许互相覆盖。
4. **不使用动画的 root motion**（ADR 0024 D1 的结论不变）：转向只是朝向，位移仍由 `cmd:walk` + `shell` 的纯函数物理负责。
5. 偏航角进内部诊断（`getDiagnostics().motion.walkYaw / walkYawTarget`），自检据此断言"起步转向 ±90°、停步回 0"。

### D2 表情：**面空间贴图绘制**（不是 UV 猜坐标，也不是屏幕空间叠加）

#### D2.1 为什么不用屏幕空间叠加面片/overlay

叠加面片会**盖在刘海之上**：本资产左眼被一缕刘海遮挡（截图可见），overlay 无法参与深度测试，画出来就是"眼睛浮在头发上"。贴图编辑天然尊重遮挡关系，因此只能走贴图。

#### D2.2 怎么在"脸上"画：面空间表面（CPU 栅格化）

1. 加载后一次性把 `EyeMouth` 材质组的三角形抽成 `{面空间 (x,y), UV}`（`facial-geometry.ts`），再用**逐三角形重心插值**把贴图像素映射到面空间坐标（`rasterizeFaceLocal`）。这是唯一精确的做法：UV→面空间是弯的。
2. 每个贴图像素记录它在**眼局部坐标** `(ex, ey)`（或嘴局部 `(mx, my)`）中的位置，形成"面空间表面"（紧凑数组，只存真正落在眼窝里的像素）。
3. **按实际像素分布重新归一化**（1%/99% 分位）：眼包围盒包含睫毛与高光条，而虹膜画片占的 UV 面积巨大、集中在包围盒偏下位置。**不做这一步的实测后果**：`squint`（眯眼）与 `droop`（下垂）只改到 0.05% / 0.12% 的贴图（几乎没变化），而"整只眼重画"的 `closed-arc` / `wide` 有 19% / 22%。归一化后四种眼型都在 9%–19%，肉眼可辨（截图见下）。
4. 接受域是**矩形**（= 眼包围盒），不是椭圆：椭圆会在包围盒四角留下原虹膜的边缘，渲染出来是一圈"幽灵眼环"（实测截图确认）。
5. 眼型图元必须镜像对称（D2 背景的第 2 条事实）。

#### D2.3 `emotion` → 图元映射（`EMOTION_FACE`，纯函数）

| emotion | 眼（`EyeShape`） | 嘴（`MouthShape`） | 红晕 | 与 §4.5 的关系 |
|---|---|---|---|---|
| `neutral` | `none` | `none`（回静态闭嘴帧） | 0 | 无额外表情 |
| `happy` | `closed-arc`（∩ 形弯眼） | `smile`（嘴角上扬） | 1 | "嘴角上扬 + 眼型变化" ✅ |
| `sad` | `droop`（外侧眼睑下垂） | `frown`（嘴角下垂） | 0 | "眉内侧下压"→ 本资产做不到（贴图改不了眉毛形状），用眼睑下垂表达同一语义 |
| `surprised` | `wide`（重画更大的眼：眼白+虹膜+瞳孔+高光） | `open`（微张） | 0 | "睁眼 + 张口" ✅；张口只作用表情，不夺口型通道 |
| `shy` | `squint`（半闭/眯眼） | `small`（小口） | 2 | "视线下移 + 颊部"：颊部用红晕 ✅；`>_<` 因左右眼共用 UV 不可区分 → 取 §4.5 给出的另一选项"半闭" |
| `angry` | `half`（半闭眼睑） | `none`（抿嘴＝静态细线） | 0 | "眉下压"→ 同上做不到，用半闭 + 抿嘴表达 |
| `sleepy` | `half`（半闭） | `small` | 0 | "半闭眼" ✅ |

不做的事：不新增 emotion 值、不改 §4.5 表格、不引入 blendshape（本资产没有）、不动 `RenderState`。

### D3 通道优先级：口型 > 摸头 > 表情 > 静态闭嘴

1. 仲裁抽成纯函数 `resolveMouthOwner({speaking, lipSyncDriven, patActive, emotionMouth, alpha})`，渲染侧照它的结论画嘴（§5.2 口型通道最高优先级的可执行形式）。
2. 表情**只接管嘴部底板**；说话时嘴层永远是图集帧（口型），表情嘴型让位——**不破坏既有口型驱动**。
3. 摸头（`reacting` + `pat_react`）在说话时本来就不改嘴型（ADR 0014 D6），非说话时它的 shy 帧优先于表情嘴型；表情的"临时投影 shy"（§5.3）由 `getState().emotion` 与贴图各自投影，二者口径一致。
4. 表情层淡入 0.25 s（§5.2 既有规定），淡入只作用于表情层，不影响口型帧。

### D4 合成实现（不闪、不卡、可观测）

| 措施 | 原因/实测 |
|---|---|
| `base` 画布只在创建时画一次（原贴图 + 肤色底板），之后只读 | 任何重绘都从 base **按脏矩形**还原，绝不整张清空 |
| 重绘只碰脏矩形（眼区、嘴底板、颊部） | 上一版每次 `setFrame` 清空整张 1024² 再重绘（502k 像素/次），是"整脸刷新"的根源 |
| 眼睛画在**独立透明层**上，再按 `alpha` 合成 | 眼睛占 52 万贴图像素，逐像素重绘一次 ≈40 ms；淡入 6 步会卡 0.24 s。分层后每步 ≈3.6 ms（实测 78 ms → 3.6 ms） |
| 逐像素采样用**打包整数**（0xRRGGBBAA，0 = 不画） | 热路径禁止分配对象；50 万像素/次的 `{r,g,b,a}` 会让 GC 抖动 |
| 左右眼表面**去重** | 两眼共用 UV，不合并会把像素量翻倍（1,048,770 → 524,408） |
| 材质 `map` 只在创建时替换一次，之后只 `needsUpdate` | 不重建贴图、不重编译材质 → 不闪 |
| 状态指纹去重（眼型/嘴型/红晕/优先级/alpha 量化） | 无变化不重绘；淡入切成 6 步（0.25 s） |
| 诊断：`faceDistance`（与基线缩略图的平均绝对差）、`textureDigest`、`lastRepaintMs/lastPaintPixels` | 截图受 Idle 动画与视线漂移影响（噪声底实测 ≈6000/84864 ≈ 7%），**像素差不能证明"贴图变了/还原了"**；缩略图平均差与指纹可以（0..1，实测情绪态 8.6%–19.4%、还原后 0.000） |

性能实测（本机）：首次绘制/换眼型 ≈40 ms（一次性），淡入每步 ≈3.6 ms，静态闭嘴重绘 ≈0.6 ms，贴图 1024²（128² 源 × 8× 超采样）。

| 缺失项 | 行为 |
|---|---|
| `EyeMouth` 材质或原贴图 | 整条通道空转 + 一条 WARN；角色正常显示、动作正常（§11） |

| `Face` 材质（脸皮） | 只禁用红晕层，眼型与嘴型照常 |

## 替代方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 屏幕空间 overlay 面片画表情 | 实现最快、表情最自由 | 会盖在刘海之上（本资产左眼被刘海遮挡），无法参与遮挡 | 否 |
| 修改 GLB 加 blendshape | 最"标准" | 需要重做资产；契约/ADR 0010 已明确不做 | 否 |
| 按 UV 矩形直接贴眼型图 | 代码最少 | UV→面空间是曲面映射，实测会错位（残差与岛尺度同量级） | 否 |
| 只做"抹掉眼睛 + 画弧线"（不分类眼型） | 简单 | 只能表达"闭眼"，无法表达 >_< / 下垂 / 睁大 | 否 |
| **面空间栅格化 + 纯 Canvas 图元（本方案 D2/D4）** | 精度高、尊重遮挡、零依赖、可单测、无 blendshape | 需要一次性标定与 CPU 栅格化；眼型受"镜像对称"限制 | **是** |
| 走动时不转身，改用侧身行走片段 | 不用写转向 | `Move_Ing`/`Carrier2_Walk` 是侧身战斗片段（ADR 0023 实测），正面桌宠不合适；且位移方向由代码决定，片段无法自适应左右 | 否 |

## 后果

**正面**

- 走路不再"侧滑"，转向与停下都是平滑的；转身角度进诊断，有断言可回归。
- `emotion` 第一次真正上了脸：四种情绪在截图上肉眼可辨（弯眼+笑、眯眼+红晕、下垂眼+撇嘴、睁大眼+张口），且**没有任何按次调用**（纯 Canvas + 本地贴图）。
- 贴图级断言（`faceDistance`/`textureDigest`）把"表情生效 / 还原 neutral"变成确定性可测项，不再依赖受姿势影响的像素差。
- 口型通道优先级未被破坏：说话时嘴层始终是图集帧（自检断言 `mouthOwner`）。

**负面 / 成本**

- 眼型受"左右眼共用 UV"限制，必须镜像对称；`>_<` 只能取"半闭"的近似（§4.5 允许）。
- 眉毛类表情（§4.5 的"眉内侧下压""眉下压"）实现不了：眉毛形状是几何体，贴图只能改颜色。替代方案见 D2.3，**这是资产限制，不是实现遗漏**。
- 换眼型时有一次 ≈40 ms 的层渲染（一次性，可接受）；淡入每步 3.6 ms。
- 标定常量（`plateUv`、眼/颊锚点派生规则）与资产强相关，换模型必须重新标定并复核截图。

**约束**

- 不得整体替换 `EyeMouth`/`Face` 贴图（会丢原画）；只能"以原图为底 + 局部合成"。
- 不得在像素热路径里分配对象（用 `xxxInto` + 打包整数）。
- 不得为了表情把口型通道降级（`resolveMouthOwner` 的优先级就是契约 §5.2）。
- 不得新增 `emotion`/`intent` 值，`RenderState` 字段不变。

# D6 决策变更（第 2 版，2026-10-31）：**废弃程序化重绘，改为官方表情差分贴图**

> 本节记录一次**决策反转**：上面 D2 的"面空间 + 程序化图元"路线在实机上被判定失败。

## D6.0 结论先行

| 项 | 旧（第 1 版 D2/D4） | 新（本版 D6） |
|---|---|---|
| 眼型来源 | 代码在 Canvas 上画弧线/瞳孔/眼睑 | **只来自 `data/expressions/*.png`**（官方差分） |
| 红晕来源 | 代码画粉色径向渐变 | **只来自 `data/expressions/blush.png`** |
| 嘴型 | 代码画弧线（保留） | **不变**（不涉及眼型，且口型优先级不受影响） |
| 面空间栅格化 | 用于画图元 | **保留**：用于把 PNG 贴到眼部 UV |
| 脏矩形 / 眼睛层 / 淡入 / 精确还原 | 有 | **保留**（架构层没问题） |

## D6.1 为什么判定失败

实机截图（第 1 版 `dist/selftest/window-emotion-*.png`）暴露的问题，按严重度排序：

1. **"恐怖谷"**：程序化画的眼白/虹膜/高光是纯几何图形，与官方画风（线稿 + 水彩渐变 + 高光点）完全不同源；斜视时尤其像贴上去的假眼。
2. **形状表达力不足**：为了让形状落在真实可见的眼部，必须依赖"按像素分布重归一化"这类脆弱标定；标定一旦偏，就会画出一小块碎片或黑边（实测踩到 `percentileRange` 的哨兵 bug，症状就是"只在眼睛上画出一条细线"）。
3. **眼睑遮挡不可控**：上眼睑是独立几何体，程序化图元不知道它盖在哪，画在上半部的弧线会整条被挡住。
4. **不可持续**：每加一种情绪就要再调一套几何参数，而**官方本来就有一套现成的表情差分**——重造轮子在美术上永远打不过原作。

**根因**：情绪表情本质是**美术资产**，不是几何问题。程序化绘制在"能不能显示"上可行，在"像不像官方"上不可行。

## D6.2 新方案：官方差分 → 面空间投影 → 覆盖眼部 UV

```
data/expressions/{eyes_happy,eyes_shy,eyes_sad,eyes_surprised,blush}.png
  → pet-asset://asset/expr/<file>   主进程只读、文件名白名单（EXPRESSION_FILES）
  → PixelImage{width,height,data}   渲染进程解码成像素缓冲
  → 眼型：逐像素 (ex,ey) 采样 PNG → 写入眼睛层 → 按 alpha 合成到 EyeMouth 的眼部 UV
  → 红晕：颊部椭圆内采样 blush.png（乘以强度）→ 叠加到 Face 贴图
  → 贴图只按脏矩形更新；0.25s 淡入；情绪结束用 ImageData 快照精确还原
```

关键约定（写进 `data/expressions/README.md`）：

1. **单眼图 / 双眼条**：宽高比 < 1.6 视为单眼（两只眼共用），≥ 1.6 视为双眼条（取左半，因为左右眼共用 UV）；
2. **满幅 vs 透明**：两种都支持——透明处不绘制（原贴图透出），不透明处覆盖；推荐"满幅整眼"（含肤色底），语义就是"整只眼被换掉"；
3. **拉伸语义**：图片按**当前模型眼部包围盒**铺满（本资产宽:高 ≈ 2:1），因此官方差分若是"贴图空间的眼部裁剪"，拉伸正是需要的；若是手绘方形眼图，则图案应画在画布垂直中段并横向铺满；
4. **降级**：任何一张缺失 → 该层不生效（缺眼型则保持默认眼、缺红晕则不叠），**只记一条 WARN，不阻断表情系统**（任务 2.3）。

## D6.3 还原：用 ImageData 快照，不用 drawImage

第 1 版的还原是"从 base 画布按矩形 `drawImage` 拷回来"，矩形边界会留 1 texel 的抗锯齿差——指纹会变、画面看不出，但"完全还原"无法断言。
本版在通道初始化时对**眼区 / 嘴底板 / 颊部**各拍一张 `ImageData` 快照，还原时 `putImageData` 逐像素覆盖（不做混合）。
效果：`faceDistance` 在恢复 neutral 后是 **精确 0**（自检断言 ≤0.2%）。

## D7 官方线稿贴花层（`face-decal.ts`）

### D7.1 为什么另起一层，而不是继续往 EyeMouth 里合成

拿到官方资产后确认：**游戏自己给 3D 小人做表情，用的就是平面贴花**——
`FX_MESH_CH0335_Prop_Face_01/02/03.glb` 是 **z 轴厚度为 0 的平面**（193 / 145 / 50 顶点），
配 `FX_TEX_CH0335_Img_Face_01.png`（3×3 线稿：3 种眼型 × 左右 + 3 条嘴线）。

线稿**只有线、没有肤色底**：把它投影进眼部 UV 会把原虹膜露在下面，变成"睁眼 + 闭眼线"叠加。
贴花天生就是叠加层，所以这一层独立存在，与 D6 的贴图合成互不干扰（D6 负责眼型差分与红晕，
D7 负责眨眼与嘴线）。

### D7.2 为什么不违反 D2.1（"不用屏幕空间 overlay"）

D2.1 反对的是**屏幕空间**叠加：它不参与深度测试，会盖在刘海之上。D7 的平面：

- 挂在 **头骨**（`Bip001_Head`）下，骨骼动画直接带着走；
- `depthTest: true` + `polygonOffset`，位置在脸部表面略靠前（`SURFACE_LIFT = 1.2e-4` 模型单位）；
- 因此刘海挡在前面时仍然遮挡——与真实眼睛的遮挡关系一致。

### D7.3 位置怎么定（不靠手调）

加载后从 `EyeMouth` 网格量：

1. 遍历该 primitive 的三角形，按 UV 分岛（嘴底板 `u<0.25 && v>0.75`，其余为眼）；
2. 两块各求**世界空间**包围盒中心与尺寸；
3. 换算回头骨局部空间（模型根带 `pixelsPerUnit≈5.7 万` 缩放，直接当局部坐标会差五个数量级——实测踩过）；
4. 左/右眼各一块平面，右眼镜像（`texture.repeat.x = -1`），嘴一块，腮红两块。

### D7.4 贴图来源与降级

- `eyes_closed.png` / `eyes_half.png` / `eyes_wide.png` / `mouth_line.png` / `mouth_open.png`
  由 `FX_TEX_CH0335_Img_Face_01.png` 按**连通域**裁出（3×3 网格并不规整：嘴线在 y≈126/292/466，
  眼在 y≈35/198/345，按格子切会串行）；
- 走 `pet-asset://asset/expr/<file>` 白名单（`src/shared/expression-files.ts` 的 `DECAL_FACE_FILES`）；
- 任一贴图缺失 → 整层不启用，只记一条 WARN（§11），不阻断启动、不影响 D6 通道。

### D7.5 驱动

| 行为 | 驱动源 | 表现 |
|---|---|---|
| 眨眼 | 内部计时（2.6–6s 随机） | 140ms 三角包络，线稿透明度 0→1→0 |
| 嘴型 | 表情嘴型（D6 的 `mouthOwner`） | `mouth_line` ↔ `mouth_open` 切换 + 张口时放大 35% |
| 腮红 | `emotion.blush`（0/1/2） | 透明度 0–85% 淡入 |

眨眼**不占用** `RenderState`，也不新增事件——它是 Base 层的常驻表现，与呼吸同级。

### D7.6 约束

- 贴花层不得写 `head` / `eyeL` / `eyeR` 的 `quaternion`（骨骼仲裁的唯一写者是 `bone-arbiter`）；
- 贴花平面必须参与深度测试，禁止 `depthTest: false`；
- 贴花位置必须从网格量出来，不得硬编码世界坐标（换模型即失效）。
