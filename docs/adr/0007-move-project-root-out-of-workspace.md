# 0007. 把工程根目录迁出工作区（`D:\aa3dpet` → `D:\aa3dpet-app`）

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-27 |
| 决策者 | 项目所有者 |
| 关联 | 承接 #0006 的待定项；`CONTRACTS.md` §16.1（已同步）、§15（1.2.1） |

## 背景

ADR 0006 确认：可执行文件位于 `D:\aa3dpet`（本会话工作区）之下时，Electron 固定以 `0x80000003` 在 Chromium 初始化阶段退出；同一份工程放到工作区外任意目录都正常（`D:\petapp`、`D:\pettest`、`D:\aa3dpet2`、`C:\Users\<user>\pet-test`、`D:\acl-probe` 实测均为 exit 0）。

0006 把"是否搬迁"留给项目所有者决定，理由是搬迁会改动 §16.1 的根路径与所有文档中的路径。所有者选择搬迁。

## 决策

1. 工程根目录迁到 **`D:\aa3dpet-app`**，`D:\aa3dpet` 只留一个 `MOVED.txt` 指针。
2. `CONTRACTS.md` §16.1 的"工程根目录"改为 `D:\aa3dpet-app`；版本按 §15 升 patch 到 **1.2.1**（只改路径与说明，不改任何规则、状态、事件、接口）。
3. 迁移后必须重新验证：构建、类型检查、24 个单测、完整自检（窗口属性 + 三件产物）。任一不通过则视为迁移失败。

## 替代方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 源码留在工作区，运行目录用 `D:\petapp` 同步 | 不动契约 | 每次运行前同步约 400MB；源码与运行产物分布在两处，迟早出现"改了没同步"的假故障 | 否 |
| 继续排查工作区目录为何被区别对待 | 可能根治 | 属系统/harness 层，不在项目可控范围 | 否 |
| 迁到 `D:\aa3dpet-app`（本方案） | 一次到位，`npm start` 直接可用；保留原目录作为指针 | 需要改 §16.1 与文档路径（patch） | **是** |

## 后果

**正面**

- 开发、运行、验收回到同一个目录，不再有同步环节，也不再有"工作区外才能跑"的心智负担。
- 目录名只差一个 `-app`，从旧路径迁移的人不容易走错。

**负面 / 成本**

- 历史 ADR（0006）与 `MODULE_STATUS` 的坑位里仍写着 `D:\aa3dpet` 的证据，那是当时的事实，不追改；只在新文档里指向前缀。
- 若以后 harness 又把 `D:\aa3dpet-app` 纳入某种策略范围，需要重新评估（届时先复跑 `npm run selftest`）。

**约束**

- 任何人不得把工程根目录移回 `D:\aa3dpet` 或其他被策略覆盖的目录，除非先证明该目录下 Electron 能正常启动。
- 迁移/改根目录属结构性变更：必须同步 §16.1、升 patch、并在 `MODULE_STATUS` 变更记录里留一行。
