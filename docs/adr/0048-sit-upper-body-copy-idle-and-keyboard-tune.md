# 0048. 坐姿上半身直接照抄站立姿态（放弃欧拉/基底换算），加键盘微调

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-11-05 |
| 决策者 | 项目所有者（"放弃所有复杂的世界欧拉角、基底四元数差值计算，改用最暴力的绝对视觉对齐"） |
| 关联 | 契约 §7.3（render 表现规则）；ADR 0014（骨骼仲裁）、ADR 0026 D6.6（表情只走贴图）、ADR 0044/0045/0046（坐姿微动与头部基准，**D2.1 的基准换算被本 ADR 废止**）、ADR 0047（脸部特写取证，**D2 的"站立世界 pitch 对齐"被本 ADR 取代**） |
| 修订 | **ADR 0051**：覆盖链从胸/颈/头三根扩为**下背 `Spine` + 胸 + 颈 + 头四根**；采集时机改到 `BoneArbiter.beginFrame()` 之后并用 `animationBase()`；覆盖权重改为阶段 B 的 `stageBBlend × sitGain × sitDrop`（0.3s）。本 ADR 的"直接覆盖、不做差值"原则不变 |

## 背景

ADR 0045 → 0046 → 0047 连续三轮都在用"相对某个参照系的旋转差"补偿头部：

- 0045：相对**绑定姿态**量低头 → 补偿把脸抬过头；
- 0047：改成相对**站立时头骨的世界 pitch** → 特写里虹膜仍偏上，又加了一个 `0.10rad` 的低头常量。

真机反馈（本轮）：B 图**下巴内收**、眼神继续向下；那个 `0.10` 更是"本来就低头还往下压"。
结论：**任何"参照系 + 差值"的方案都会被参照系本身带偏**，而且很难用肉眼验收。

## 决策

### D1 上半身直接覆盖为站立姿态（不再做任何换算）

- 站立待机、纯待机的那一帧（无拖拽/坐姿/一次性演出/小动作、朝向回正、Idle 权重 ≥0.9），
  把 **胸（`Bip001 Spine1`）/ 颈（`Bip001 Neck`）/ 头（`Bip001 Head`）** 三根骨骼的
  **局部四元数**各存一份（`idleUpperLocals`）。
- 坐姿停帧后，每帧用
  `slerp(片段姿态, 站立局部四元数, sitGain)` 作为这三根骨骼的**旋转基底直接覆盖**：
  `BoneArbiter.overrideBase()`，**不叠任何差值、不做欧拉分解、不加固定偏移**。
- 为什么是三根而不是只改头：坐姿片段的骨盆/脊柱把躯干摆成另一个角度，只改头会让脖子拧着、
  下巴内收——这正是上一轮"B 图"的病灶。
- 呼吸、自主张望、眼睛基底这些**叠加量**照旧叠在这份基底之上，所以人还是活的
  （自检里"头真的在动"仍然通过）。

### D2 键盘 ↑/↓ 现场微调（把"肉眼平视"调出来）

- `RenderModule.setSitHeadTune(rad)`：坐姿头部的固定微调（正 = 低头），夹 ±0.4rad，
  跟着 `sitGain` 淡入；叠加在头骨上，不影响 D1 的覆盖。
- `window.diagnostics.headTune(rad)` 与键盘 **↑/↓**（Shift = 大步 0.1rad，普通 = 0.02rad）
  共用同一个入口，所以"调出来的数"、"截图里的数"、"写死的数"是同一个。
- 说明：桌宠窗口 `focusable: false`（§3.2），平时收不到键盘事件。**正式运行不注册任何键盘
  监听**：键盘通道只在窗口地址带 `?tune=1` 时挂载（`installHeadTuneKeys()`），
  自检用 `headTune()` 走同一入口完成扫描取证。
- 扫描取证：`face-tune-{m20,m10,p0,p10,p20}.png`（仅头部 pitch 变化），
  以及拼图 `logs/evidence/face-tune-sweep.png`。
- **定档：`SIT_HEAD_TUNE_RAD = 0`**（= 完全照抄站立姿态）。再往下 0.10/0.20 明显低头、
  眼型变窄、刘海压住眼睛；往上则下巴上扬。

### D3 如果还有"看下方"，下一步只动贴图

眼骨与头骨都验证过：这张 `EyeMouth` 是近平面卡片，虹膜是**画在贴图上**的
（ADR 0047 排查 2：眼骨 ±0.35rad 画面几乎不变）。因此"虹膜在眼眶里的位置"**不能**靠骨骼改，
只能改贴图（把虹膜像素整体上移 / 叠一张正视眼型贴花）。本轮 D1+D2 已把头部姿态对齐到站立，
若肉眼仍不满意，下一轮直接做贴图通道，不再碰骨骼。

## 替代方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 继续调"相对参照系的差值 + 常量" | 不动架构 | 三轮都被参照系带偏，且无法肉眼验收 | 否 |
| 只覆盖头骨（胸/颈不动） | 改动最小 | 脖子拧着、下巴内收（上一轮 B 图） | 否 |
| 三根骨骼局部四元数直接覆盖（本方案） | 与玩家认可的站姿**逐位一致**，无需标定 | 依赖先在待机时采一次 | **是** |
| 坐姿不停帧、直接播片段开头 | 省事 | 片段本身就带低头，眼神问题原样保留 | 否 |
| 改贴图（虹膜上移 / 贴花） | 唯一能真正移动瞳孔的路 | 需要逐张核对贴图，改动大 | 暂缓（D3） |

## 后果

**正面**

- 坐姿的上半身姿态 = 站立姿态（同一组局部四元数），下巴不再内收（`face-tune-p0.png`）。
- 不再有任何"头部基准/欧拉角/差值"代码：`captureSitHeadLevel()`、`measureEyePitch()`、
  `SIT_HEAD_AIM_DOWN_RAD`、`sit.headRawPitch/headLevelPitch/eyeRawPitch/idleHeadPitch/headWorldPitch`
  全部删除。
- 有现场微调通道（键盘/诊断），下次不满意不用改代码就能找到合适值。

**负面 / 成本**

- 站立姿态只在第一次纯待机时采一次；换了模型/骨架要重新确认。
- 覆盖三根骨骼意味着坐姿的"躯干前倾"也被抹平：她坐得比片段原姿态更**直**（这是刻意的取舍——
  宁可坐直，也不要低头）。
- 键盘通道在 `focusable: false` 的正式窗口里收不到事件（仅调试可用）。

**约束**

- 不得再引入"相对绑定/站立姿态的差值"类补偿；要动就动**局部四元数覆盖**或**贴图**。
- 不得写眼皮骨（`bone_eye_D_*`）的任何通道（沿用 0046）。
- 微调量只写在 `shared/constants.ts` 的 `SIT_HEAD_TUNE_RAD`。
- 取证接口只允许挂在 `window.diagnostics`。
