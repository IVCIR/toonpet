# 0042. 坐下过渡、吸附跟随追赶、坐姿窗口与解除后的下落

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-11-03 |
| 决策者 | 项目所有者（真机体验四问之四） |
| 关联 | 契约 §3.4（D-7）、§4.1（`sitting` / `settling`）、§5.1、§5.3、§7.2（shell 吸附）、§7.3（render 坐姿）、§11、§12（单一定时器）、§13；ADR 0028（吸附与坐姿）、ADR 0034（接近与坐姿生命周期）、ADR 0035（拖拽/落地） |

## 背景

真机体验对"坐姿 + 窗口吸附跟随"提出四点：

1. 从站立到坐下是**瞬间切换**，没有过渡；
2. 坐姿姿态生硬（旧窗口 11.2–13.5s 是"手撑着脸、闭眼、身体前塌"的一帧，观感像打盹）；
3. 坐姿时移动吸附的目标窗口，**角色没有很好地跟随**；
4. 目标窗口消失/移出边界时，只是"站着"留在原地（她脚下已经没有东西了）。

### 排查

| 现象 | 根因（读码 + 实测） |
|---|---|
| 坐下瞬间 | `enterSit()` 直接 `playHold('sit', 0.45)`：`snap_applied` 到达前她在走路/站立，到达后 0.45s 内**纯交叉淡入**到坐姿。骨骼旋转线性混合读作"融化"，没有任何"屈膝、重心下降"的过程 |
| 坐姿生硬 | 窗口把第一帧（13.4s 的"撑起身子"）当成整段姿态；旧窗口 11.2–13.5s 的三个问题：闭眼、手撑脸、前塌。而同一段演出 14.3–15.6s 是"手放膝上、睁眼、大腿水平、小腿垂下" |
| 跟随差 | `snap.tick` 的跟随**固定 120ms 节流**（8Hz）。目标窗口被拖动时每帧都在动，8Hz 的跟随必然一顿一顿；`followChecks` 日志显示拖动 900ms 内只重算 7 次 |
| 解除后悬空 | `snap_released` 之后没有任何一方动窗口：`clicked`/`command` 时目标窗口还在（站在边缘合法），但 `window-gone`/`fullscreen` 时她悬在空气里 |

## 决策

### D1 坐下过渡：`snap_applied` 之后 240ms 的"半蹲"

`snap_applied` 到达（窗口已贴到边缘、`sitStartedAt = now`）之后的前 `SIT_LOWER_MS = 240ms`，
在官方坐姿片段之上叠一段**一次性的过渡**（`sit-pose.ts` 的 `sitPose()` 输出）：

| 量 | 起点（t=0） | 终点（t=240ms） | 表达 |
|---|---|---|---|
| `transitionLiftPx` | **+14px** | 0 | 身体从座面**上方**落下（不是从下往上顶） |
| `thighBend` | **0.22rad** | 0 | 屈膝/屈髋（负 pitch = 腿前抬，ADR 0035 D5 标定） |
| `lean` | **0.05rad** | 0 | 躯干微前倾 |

- 三条都用 `1 - easeOutCubic` 衰减，240ms 后**恒为 0**，之后只剩官方片段的姿态 + 呼吸浮动。
- 与 0.45s 的片段交叉淡入**同时**发生：前半段"屈膝下沉"、后半段"片段接管坐正"。
- 只在**首次落座**时发生：`enterSit` 保留 `sitStartedAt`（改吸另一扇窗时不重播"坐下去"）。
- 程序化降级路径（没有坐姿片段）不加这次抬升 —— 它的"落下"由已有的 `SIT_DROP_PX = 24px` 下沉表达。

### D2 跟随：目标在动时进入"追赶模式"（仍是同一个 16ms 轮询器）

```
catching_up = now < catchUpUntil
interval    = catching_up ? min(followIntervalMs, 16ms) : followIntervalMs
```

- 检测到目标矩形变化（≥1px）→ `catchUpUntil = now + SNAP_FOLLOW_SETTLE_MS(220ms)`；
  接下来 220ms 内**每拍都重算**（≈60Hz），目标停止变化后自动回落到 120ms 常规节流。
- **不新增定时器**（契约 §12）：仍然挂在既有 16ms 指针轮询器的 `onTick` 上。
- **不新增通道**：目标矩形仍由 `GetForegroundWindow` + `DWMWA_EXTENDED_FRAME_BOUNDS`
  （失败退回 `GetWindowRect`）取得，`readHandle(handle)` 按句柄重读。
- **不做位置插值/弹簧**：每拍直接写"当前目标边缘对应的整数位置"，比插值少一帧延迟；
  窗口位移本身是整数像素，插值只会引入额外的滞后。
- 诊断：`SnapDiagnostics.catchUp` / `catchUpTicks`（"跟随是不是真的在跟"的数字证据）；
  日志只在**进入**追赶那一拍打一条，避免 60Hz 刷屏。

### D3 坐姿片段换成 13.4–15.6s，并按**停帧那一帧**标定补偿

- `clip-bank.sit`：`startSeconds 13.4`、`maxSeconds 15.6`（原 11.2–13.5）。
  这 2.2s 里她先"撑起身子坐正"（13.4→14.3），再稳定在"手放膝上、睁眼、大腿水平、小腿垂下"（14.3–15.6）。
  `playHold` 停在 15.6s，正好是这个姿态。
- `calibrateSitPose()` 改为：`playHold` → **`holdSeek(片段末尾)`** → 采包围盒 → 还原 Idle。
  旧实现量的是片段**第一帧**（前塌姿态），补偿量会偏；现在量的是她 99% 时间实际停留的那一帧。
  （`ModelAnimations` 因此新增 `holdSeek(seconds)`。）
- "像不像坐在边缘"的验收：桌面合成截图
  `dist/selftest/window-sitting-desktop.png` —— 她坐在记事本窗口的**上沿**，两条腿垂在窗口前面。

### D4 解除：`window-gone` / `fullscreen` 之后落回桌面

- **唯一写窗口位置的地方仍是 shell**。`emitReleased` 之后，若 `reason ∈ {window-gone, fullscreen}`
  且离工作区地面线超过 `SNAP_RELEASE_FALL_MIN_PX = 48px`，就走 `motion.startSettle({vx:0, vy:620})`：
  复用**回弹弹簧**（同一 16ms 轮询器、同一 `settling` 语义），不新增状态、不新增定时器、不新增 IPC。
- 为什么只在这两个 reason 下落：`clicked` / `command` / `dragged` 时目标窗口还在，
  她站在（或坐在）那条边缘上是**物理成立**的；只有窗口消失/全屏才真的"脚下没东西"。
- render 侧：`snap_released` 已经按 reason 播 `startle`（`window-gone`/`fullscreen` 是 `STARTLE_LOST_MS = 320ms`
  的"后仰看左右 + 双臂外展 + 临时 surprised"）。**不给这次下落伪造冲击速度**：
  ADR 0040 D3 的口径是"轻放不缩"，而窗外沿掉到桌面既没有"松手瞬间竖直速度"这个事实，
  落差也只有几十到几百像素 —— 所以这次落地不叠下蹲，只由惊跳 + 弹簧表达。

### D5 契约与可观测

- **不新增**状态名、事件、`intent`、`emotion`、IPC 通道、`RenderState` 字段、依赖、定时器。
- 内部诊断：`RenderDiagnostics.sit.transition` / `transitionLiftPx`；
  `SnapDiagnostics.catchUp` / `catchUpTicks`。
- 契约 §7.3 的坐姿规则（窗口与标定口径）、§7.2 的跟随节流、§11 的降级行、§12 的跟随行同步（minor，1.18.0）。

## 替代方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 只在 `clip-bank` 里换窗口，不加过渡 | 改动最小 | 交叉淡入仍然是"融化"；用户要的是"半蹲过渡" | 否 |
| 用片段自己的 10.4–11.4s"坐下去"那一段当过渡 | 完全官方 | 那一段带**根位移**（走向椅子），落点对不上窗口边缘；且 10.4s 时她还站着，与 `snap_applied` 的时刻不同步 | 否（改用 240ms 程序化半蹲） |
| 跟随改成每拍都重算（永远 60Hz） | 实现最简单 | 空闲时每拍一次 Win32 查询 + 一次 `setPosition`，无意义开销，且 `setPosition` 会打断 Windows 的窗口动画 | 否（按需追赶） |
| 跟随用弹簧/插值平滑 | 视觉更"软" | 多一帧延迟，且落点会滞后于窗口边缘（贴边看起来"没贴住"） | 否 |
| 解除后瞬间 `setPosition` 到地面线 | 最省事 | 瞬移穿帮；且绕过了回弹（`motion_ended{settle}`）与 R-8 的穿透约束 | 否 |
| **240ms 半蹲 + 按需追赶 + 停帧标定 + 复用回弹下落（本方案）** | 零新状态/定时器/通道；每一步都可单测或截图验收 | 半蹲是程序化的（不是资产动作）；窗沿落差 < 48px 时不落下 | **是** |

## 后果

**正面**

- "站起来 → 屈膝 → 坐上边缘"有了因果；坐姿是"坐正、手放膝上、睁眼"，不再是打盹。
- 拖动被吸附的窗口时，她以 ≈1 帧延迟贴着边缘走（`catchUpTicks` 可证），松手/停下后自动回到省电节流。
- 目标窗口关掉时她会惊跳一下再落回任务栏，不再悬在半空；`clicked`/`command`/`dragged` 的语义不变。
- 新增 4 条主链路自检（半蹲过渡、追赶模式、落回地面线、轻放不缩）+ 1 条 `snap` 单测（追赶节流）。

**负面 / 成本**

- 半蹲是**程序化**的：它是"过渡"而不是"姿态"，240ms 之后完全交给官方片段；换模型不会失效（不依赖骨骼比例）。
- 150ms 级的追赶窗口意味着拖动目标窗口时 shell 每拍都要读一次 Win32 矩形（`GetForegroundWindow` 之外多一次
  `DwmGetWindowAttribute`/`GetWindowRect`）：实测无感，但属于"移动时才付"的成本。
- 窗沿落差 < 48px（例如贴着任务栏的小窗）时**不**下落，她会站在那条边缘上（刻意如此，避免一次无意义回弹）。
- 坐姿窗口（13.4–15.6s）仍然是 CH0335 的标定值；换模型要重新量。

**约束**

- 不得为"坐下"新增状态或阶段字段进 `RenderState`；过渡只在 `sit-pose.ts` 里。
- 跟随不得新开定时器，也不得在目标静止时保持 60Hz 查询。
- 落到地面只能走 `motion.startSettle`（唯一写窗口位置的地方仍是 shell），不得让 render 动窗口。
- 不得给"窗沿下落"伪造 `drag_released` 或冲击速度（ADR 0040 D3 的口径只认真实松手速度）。
