# 0040. 头部区改由头骨半径判定；落地冲击改用松手速度并收小幅度

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-11-03 |
| 决策者 | 项目所有者 |
| 关联 | 契约 §3.3（R-10、R-4）、§3.4（D-1/D-3）、§3.5（`cmd:interactive`、`cmd:probe`）、§5.3（"拖拽松手"）；ADR 0002（掩膜命中）、ADR 0004 D1.6（head 快照采信）、ADR 0024 D2/D3（回弹）、ADR 0035 D4（落地缓冲，**口径被本 ADR 修订**）、ADR 0039（摸头改官方片段；其排查日志给出了本 ADR 的两个证据） |

## 背景

ADR 0039 上线后真机反馈：**静止点她没反应**，而**拖拽落地会"弹一下"**。按所有者要求先加日志排查（`[drag-gesture]` 三段打点 + `[render] probe` 头部带几何 + 落地/反跳事实），两个根因都有了数字证据：

**① 头部区覆盖不到脸。** `cmd:interactive.head` 由"掩膜 alpha 包围盒顶部 22%"推出（R-10）。本资产的**光环**（`HaloRoot` 的粉色方块）在掩膜里同样不透明，把包围盒顶部顶到光环上沿：

```
bandBottomCssY = 228.6 ~ 275.4   ← 22% 的下边界（光环 + 发顶）
headBoneCss.y  = 343.5           ← 头骨真实位置
竖向探针：y=101..216 → head=true；y≥245 → head=false
点脸 (211, 398)：hit=true, head=false, blockedBy="head-not-in-band"，head_patted 不发出
```

即：**头部带 = 光环 + 发顶，脸在带外**。实测一轮运行里 `head_patted` 只在"点光环顶部"时触发。ADR 0035 D1 早就记过"包围盒顶部可能包含光环，不适合当头部基准"，但那只改了拖拽抓取分类，摸头的入口一直在用 bbox。

**② 落地"弹一下"= 窗口反跳 + 8% 全身压扁。**

```
开始回弹 {"from":{"y":12},"velocity":{"vy":-2387},"groundY":232}
回弹触地反跳 {"bounce":1,"vyBefore":948,"vyAfter":-169}      ← 整块窗口弹起（15–40px）
回弹结束 → 落地缓冲 impact=1.00 vDown=1500px/s squashMax=0.0800 durationMs=300
落地缓冲结束（1.00） 峰值 scale.y 压扁=0.0798
```

`impact=(vDown−150)/1000` 在 vDown>1150 时饱和；而 `vDown` 取的是 **settling 期间窗口向下峰值速度**——弹簧自由落体几乎必然超过 1150，于是**每次拖拽都按"重摔"压满 8%**。两个效果叠加，看起来就是"被截断的摸头"。

## 决策

### D1 头部区 = 以头骨为圆心、`0.125 × 内容区高度` 为半径

`cmd:interactive.head` 改由**渲染侧**判定（它本来就持有骨骼与内容区尺寸）：

```
head = hit && |点 − 头骨(内容区 CSS)| ≤ HEAD_PAT_RADIUS_RATIO × 内容区高度
```

- `HEAD_PAT_RADIUS_RATIO = 0.125`（422×720 → **90px**）；实测：发顶 y≈260、脸 y≈350–420、头骨 y≈343 → 圆覆盖 253–433，恰好"发顶到下颚"；
- **光环（y≈120–205）落在圆外** → 点光环不再算摸头（这正是所有者要求的验收 2）；
- 头骨位置每帧从 `bones.head` 的**世界坐标**换算到内容区 CSS（`x = W/2 + world.x`、`y = H/2 − world.y`），因此 `walking` 的位移、`sitting` 的整体补偿、拖拽摆动都自动跟随，不需要额外标定；
- 判定仍在**渲染侧**完成、经既有 `cmd:interactive.head` 上报，**主进程的手势判定（D-2/D-3/D-4）一行没改**，`cmd:drag` 载荷不变。

### D2 降级链固定为三层，且 `null` 必须保守

| 顺序 | 条件 | 结果 |
|---|---|---|
| 1 | 模型就绪且 `bones.head` 存在 | 头骨半径（`source='bone'`） |
| 2 | 无骨骼或模型未就绪，但掩膜可用 | R-10 的 bbox 22%（`source='mask-bbox'`），保留 ADR 0039 之前的降级路径 |
| 3 | 掩膜也不可用（cold/stale/占位胶囊体） | `head = null` → 主进程按 ADR 0004 D1.6 保守丢弃，**不判摸头** |

`hit=false` 时 `head` 恒为 `false`（R-10 的"只在命中时才有意义"不变），这样主进程不需要额外判 `hit`。

### D3 落地冲击：换输入、收幅度

| 参数 | 旧值 | 新值 | 理由 |
|---|---|---|---|
| `SETTLE_RESTITUTION` | 0.28 | **0.15** | 不归零，保留一点弹性；反跳位移降到原来约一半以下，肉眼几乎看不出（ADR 0024 D2 的"轻弹一次"口径被本 ADR 收窄） |
| `LANDING_MAX_SQUASH` | 0.08 | **0.03** | 8% 全身竖压会"缩一下"，与摸头的缩身混淆；3% 是"落地一顿"而不是"动作" |
| `LANDING_DURATION_MS` | 300 | **220** | 更短，避免被读成一个独立动作 |
| `LANDING_IMPACT_MIN_PX_PER_SEC` | 150 | **700** | 轻放（松手瞬间向下 <700px/s）完全不触发下蹲 |
| 冲击速度来源 | settling 期间窗口向下峰值 | **`drag_released.vy`**（松手瞬间竖直速度，+y 向下） | 峰值必然饱和，是"每次都压满"的直接原因 |

推论（写进已知坑位）：**"往上扔"再落下的拖拽不会有落地压缩**（松手时 `vy<0`）；如果将来要按"落下高度"分级，需要另立 ADR 从窗口轨迹反推。

### D4 自检必须跟着改判据，否则会继续掩盖问题

- `computeProbePoints().head`：从"取景包围盒顶部 17%"改为**头骨位置 + 1% 窗口高度的下偏**（≈7px，落在脸上而不是颈根）；
- 自检的探针校验（`resolvePoints`）改用 `headSampleAt()` 的结论，不再用掩膜那一层的 `head`；
- 新增两条端到端验收：**点脸 → 触发且播官方片段**、**点光环（y≈0.22H）→ 不触发**；
- `头部区几何` 诊断继续打印（掩膜口径 vs 头骨口径 vs 半径），换模型时用它复核半径。

### D5 不新增契约实体

不新增状态名、事件名、`intent`、`emotion`、IPC 通道、`RenderState` 字段；`head` 仍是 `boolean | null`，只是"谁说了算"从掩膜 bbox 换成头骨。`HeadBandDiagnostics` / `HeadSample` 是内部诊断（不进 `RenderState`）。

## 替代方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 把 `HEAD_BAND_RATIO` 从 0.22 调大（如 0.40） | 一行改动 | 光环照旧顶高包围盒，带宽变大后**胸口也会算头部**；坐下/躺下时比例完全失真 | 否 |
| 让光环不参与掩膜（渲染掩膜时隐藏 HaloRoot） | 保住 R-10 字面 | 光环从此**不可点**（命中穿透到桌面）；且坐姿/回忆片段里轮廓仍会变 | 否 |
| 主进程用 `cmd:interactive` 的坐标自己算头骨 | 判定集中在主进程 | 主进程没有骨骼与内容区姿态，只能拿到掩膜；等于把渲染侧的事实再算一遍 | 否 |
| 头骨圆 + 掩膜 bbox 取**并集** | 不会漏点 | 光环又回来了（并集含 bbox 带），验收 2 直接失败 | 否 |
| **头骨圆优先 + bbox 降级（本方案）** | 与姿态/朝向天然同步；光环被排除；主进程零改动 | 半径比例是本资产标定值，换模型要复核 | **是** |
| 落地：直接把压扁设 0 | 最"平稳" | 失去重量感；ADR 0035 的意图（按冲击分级）被整体否定 | 否 |
| 落地：只改阈值不改输入 | 改动小 | 峰值饱和的本质没解决（150→700 后峰值仍 1500+） | 否（两者都改） |

## 后果

**正面**

- 点她的**脸/发顶**都能摸头，点**光环**不再误触发——判定基准从"画面统计量"变成了"角色解剖量"。
- 拖拽落地从"弹一下 + 缩 8%"变成"轻落 + 至多 3%"，且轻放完全不缩。
- 主进程手势判定、事件、通道、`RenderState` 全未改动。

**负面 / 成本**

- `HEAD_PAT_RADIUS_RATIO = 0.125` 与落地四个阈值都是**本资产 / 本机标定值**，换模型（身高比例不同）或换窗口尺寸后要用自检的 `头部区几何` 复核。
- 头骨半径是"圆形"，理论上点到她脸颊外侧的**空气**也可能算头部——但 `head = hit && …`，空气不会命中，所以不会误触。
- 向上扔再落下不产生落地压缩（见 D3）。
- 反跳没有归零，极慢的落地仍可能有 1–2px 的回弹（`SETTLE_MIN_BOUNCE_SPEED=60` 会把极小速度吃掉）。

**约束**

- 头部区只能由"头骨 + 半径"或"bbox 22%"得出，**不得**引入第三种口径（例如再叠一层固定像素带）。
- `head = null` 必须继续保持"主进程保守丢弃"，不得为了让摸头更容易而放宽成 `true`。
- 落地压缩只允许 ≤3%，且必须有速度门槛；不得为了"有手感"回调到 8%。

## 落地验证（2026-11-03，本轮实测）

- `头部区几何`：`source='bone'`、`headBoneCss.y=343`、`headRadiusPx=90`、`bandBottomCssY≈228–275`（旧口径）；竖扫 `y=350 → head=true`、`y=158 → head=false`。
- 端到端：点脸 `head_patted` +1 且 `pat.clip=CH0335_Victory_Start_Random@0.3-2.4s`；点光环计数不变。
- 落地：`impact` 由 `releaseVy` 决定（轻放 0、快速下放 >0.3），`squashMax ≤ 0.03`；`bounces` 仍是 1 但 `vyAfter` 明显变小（回弹位移约 1/2 以下）。
- 四套自检 **140 / 29 / 30 / 4** 全绿，`tsc --noEmit` 0 错。
