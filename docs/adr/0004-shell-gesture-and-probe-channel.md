# 0004. 补全 shell 手势判定与探针通道的载荷契约

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-27 |
| 决策者 | 项目所有者 |
| 关联 | `CONTRACTS.md` §3.3 R-5～R-10、§3.4 D-1～D-7、§3.5、§6.3、§7.2、§7.3、§11、§12；ADR 0002、ADR 0003；本决策使 `CONTRACTS.md` 升至 1.2.0 |

## 背景

命中与穿透已由 ADR 0002 定为"`128 × 72` 掩膜 + 主进程 16ms 轮询 + `cmd:probe` 回判"，焦点策略已由 ADR 0003 定为独立输入窗口。按这两份 ADR 落地 `shell` 时，暴露出三处**规范中缺失、实现却必须回答**的问题：

1. **头部区信息没有任何通道。** D-1/D-3 要求头部区由掩膜 alpha 包围盒顶部 22% 推出（R-10），§3.5 又说明 `cmd:drag` 的原始指针事实"用于触发 D-2 / D-3 判定"，即判定在主进程；但主进程唯一能拿到的掩膜派生信息是 `cmd:interactive{hit, x, y}`，既无包围盒也无"是否头部"，而 §7.3 明确规定"掩膜不是公共接口"。结果是 `head_patted`（唯一生产者 `shell`）按现行载荷无法在主进程侧实现。
2. **回弹结束没有跨进程信号。** R-8 要求拖拽期间保持非穿透"直到 `drag_released` 且回弹结束"，但 §6.3 没有回弹结束事件（新增事件触红线），§3.5 也没有承载 `render.getState()` 的通道（`cmd:render-intent` 是单向命令）。
3. **探针的坐标与载荷边界没写死。** `cmd:probe` 只说"内容区 CSS 坐标"，未约束缩放因子与取矩形的 API；`cmd:drag` 只说"原始指针事实"，若允许它带位移或速度，就会出现主进程与渲染侧各算一份的漂移。

此外 D-7 的多显示器钳制未指定取显示器的 API，D-8 之外也没有写明"探针失败时朝哪个方向降级"，指针落在显示器之间的缝隙时也缺少确定的判定规则。

## 决策

### D1 探针通道：载荷与判定归属

1. `cmd:probe` 的 `{x, y}` 是**窗口内容区 CSS 坐标**，原点为内容区左上角；由主进程用 `getContentBounds()` 换算（`screenPoint − contentBounds`），不使用 `getBounds()`。
2. 页面缩放因子**强制为 1**：`shell` 不调用 `setZoomFactor`，启动时校验 `webContents.getZoomFactor()`，不为 1 则重置为 1 并记一条 WARN（CSS px 与 DIP 的换算只在 1 倍时成立）。
3. 坐标映射只有一个实现，位于 `src/shared/mask.ts`，签名固定为：

   ```ts
   cssToMask(cssX: number, cssY: number, cssW: number, cssH: number): { mx: number; my: number }
   ```

   其中 `mx = (cssX / cssW) * 128 − 0.5`、`my = (cssY / cssH) * 72 − 0.5`（掩膜单元中心在 `(i + 0.5) / 128` 处，配合双线性采样）。**主进程与渲染侧禁止各写一份映射**；渲染侧的命中判定、头部判定都必须走同一份实现。
4. `cmd:interactive` 载荷为 `{ hit: boolean, x, y, head: boolean | null }`：
   - `head` 表示**该探针坐标是否落在头部区**，头部区 = 当前掩膜 alpha 包围盒顶部 22%（R-10），包围盒按 `alpha ≥ 0.5` 的单元集合计算（与命中阈值同源，保证二者不打架）；
   - 掩膜不可用（`cold` / `stale` / 采集失败）时 `head = null`，主进程不得把 `null` 当 `false` 使用，也不得据此推断任何手势。
5. **分工（本条为硬边界）**：渲染侧只回答"这个坐标是否落在头部区"；`4px` 位移阈值、`250ms` 短按时限、`800ms` 冷却**全部由主进程**基于 `cmd:drag` 的原始指针事实判定。`head` 字段只允许作为 `head_patted` 的触发条件，**不得**用于决定穿透、不得用于判断是否拖拽、不得用于反推手势，否则就滑向"渲染侧判定手势"的错误方向。
6. `head` 与按下点的对应关系：主进程在 `cmd:drag{phase:'down'}` 时快照最近一次 `cmd:interactive` 结果，仅当该结果的坐标与按下点距离 ≤ 8 CSS px 且新鲜度 ≤ 100ms 时才采信其 `head`；不满足则不触发 `head_patted`（保守丢弃，不重试、不补判）。

### D2 `cmd:drag` 的载荷边界

载荷**只有** `{ phase: 'down' | 'up', x, y, t }`：`x`/`y` 是按下点/抬起点的窗口内 CSS 坐标，`t` 是 `performance.now()`。

- 不承载位移、不承载速度、不承载任何判定结果；
- 位移与末速度全部由主进程 16ms 轮询器用 `screen.getCursorScreenPoint()` 计算（承接 D-5 与 ADR 0002 的"只有一个光标轮询器"约束）；
- 渲染侧不计算阈值、不决定手势。

### D3 拖拽结束的回弹沉降窗口

`R-8` 无法精确等到"回弹结束"，因此：

1. 收到 `drag_released` 后，主进程启动 `REBOUND_SETTLE_MS = 500` 的沉降窗口；窗口内保持非穿透，窗口计时**复用同一个 16ms 轮询器**，不新增定时器、不新增事件、不改 `render` 接口。
2. 边界一：沉降窗口内若收到新的 `cmd:drag{phase:'down'}`，窗口立即被新手势重置（清空并重新计时），**不叠加、不排队**。
3. 边界二：`500ms` 是**估计值**，不是观测值。精确对齐需要"新增只读 `cmd:state` 通道"的 ADR；不得以任何形式在当前实现里新增事件或修改 `render` 接口来换取精度。

### D4 探针丢包与降级方向

1. **单探针在飞**：上一发 `cmd:interactive` 未返回前不发下一发，彻底消除 IPC 乱序（载荷无关联 ID，不为此加字段）。
2. **200ms 超时**：按**未命中**处理，保持/恢复穿透，**禁止沿用上一次判定**。误穿透（点击落到桌面）比误拦截（点击被窗口吞掉）安全得多——后者会让用户以为系统卡死。
3. 超时记一条 WARN（同一次连续失败只记一次），**不新增事件**。

### D5 掩膜状态机：`cold` / `ready` / `stale`

1. `cold`：窗口已显示但首帧掩膜尚未就绪。
2. `ready`：最近一次成功采集距今 ≤ 100ms。
3. `stale`：最近一次成功采集距今 > 100ms（R-5 的陈旧阈值）。
4. **`cold` 与 `stale` 都不得等待掩膜**：一律落回 R-5 / R-9 的矩形判定——探针点落在内容区矩形内即 `hit = true`，矩形外 `hit = false`，`head = null`。两者各自有一个降级计数，各自在首次发生时记一条 WARN，退出时汇总。
5. 掩膜回到 `ready` 后探针立即恢复掩膜判定；`cold → ready` 的这一跳不重采（首帧就是刚采的）。

### D6 坐标 API 与 D-7 的多显示器钳制

1. 探针坐标换算用 `getContentBounds()`（见 D1）。
2. D-7 的"至少保留 80px 宽、120px 高在任一显示器工作区内"用 `screen.getAllDisplays()` **逐个求**窗口矩形与各工作区的交集，取交集面积最大的显示器；**禁止**用 `getDisplayNearestPoint()`——指针可能停在显示器之间的缝隙里，最近点会给出错误的显示器。
3. 钳制只在拖拽位移写回窗口位置时执行，不改窗口尺寸。

### D7 `render.getState()` 的跨进程轮询本轮不落地

1. §2.1 / §6.5 设想的"`shell` 以 ≤ 4Hz 轮询 `render.getState()`"在跨进程层**没有对应通道**（`render` 在渲染进程，`cmd:render-intent` 是单向命令）。
2. 本轮**不实现**该轮询，也**不发明** `invoke`/`handle` 通道去承载它——那等于绕过契约新增通道。它与 D3 的精确对齐同源，留待后续 ADR 一并解决。
3. 因此 `shell` 本轮不依赖 `RenderState` 做任何判断；`getState()` 仍是 `render` 对同进程调用方的接口。

### D8 伴生规则：显示时机、输入条定位、`input` 枚举

1. **显示时机**：无 VRM 时 `render` 不发 `model_ready`（§11），`shell` 不得等待它。显示条件 = `render` 的首帧就绪信号，取 `webContents` 的 `did-finish-load`（Electron 内部信号，不是事件总线事件）；`model_ready` 到达时走同一条显示路径，二者幂等。
2. **输入条定位**：主窗口内容区顶边上方 8px、水平居中；上方可用空间不足以容纳 `44 + 8` 时改为顶边下方 8px（ADR 0003 §2 的"角色头顶上方 8px"按本条修订为"窗口顶边"）。
3. **`input: 'keyboard'` 本期不可达**：§13 X-1 明确无 ASR，唯一入口是热键唤出的输入条，按 ADR 0003 §3 使用 `'hotkey'`。枚举不改（改名属 major），只在 `MODULE_STATUS` 记录"本期不可达，留待 ASR 模块启用"。

### D9 伴生规则：单实例与托盘

1. 第二实例被 `requestSingleInstanceLock()` 拦截后，**不**对主窗口调用 `focus()`：主窗口 `focusable` 恒为 `false`（ADR 0003），聚焦不可实现也不应实现。做法是 `showInactive()` 保置顶并记一条日志。
2. 托盘"退出"必须调用 `shell.stop()`，由 `stop()` 统一释放 16ms 轮询器、热键、托盘、窗口与单实例锁，**不得**只调 `app.quit()`；`stop()` 之后才允许退出应用。

## 替代方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| `head_patted` / `drag_started` 都由渲染侧产出（走 `evt:broadcast`） | 渲染侧本来就有掩膜，零新增载荷 | 4px / 250ms / 800ms 与主进程轮询形成两套判定，`cmd:drag` 名存实亡，正是 ADR 0002 要避免的"两侧抢状态" | 否 |
| 新增独立 `cmd:head` / `cmd:gesture` 通道 | 语义清晰 | 新增通道属契约结构改动，且绕开 `evt:broadcast` 单通道白名单 | 否 |
| 把掩膜或包围盒送给主进程自算 | 主进程完全自主 | 违反 §7.3"掩膜不是公共接口"，且每帧多传 36KB | 否 |
| `cmd:interactive` 增一个派生布尔 `head`（本方案 D1） | 只加一个布尔，掩膜仍非公共接口，判定权留在主进程 | 载荷多一个字段，需要一个 ADR 与一次 minor 升级 | **是** |
| 探针超时沿用上一次判定 | 无闪烁 | 误拦截：点击被窗口吞掉，用户以为卡死 | 否 |
| 探针超时按未命中（本方案 D4） | 最坏只是多点一次，不会吞点击 | 光标悬停时可能短暂闪回穿透 | **是** |
| 回弹结束由 `render` 发新事件 | 精确 | 新增事件名，触 §6.3 / N-8 红线 | 否 |
| 固定 500ms 沉降窗口（本方案 D3） | 零新增通道、零新增事件 | 是估计值，极端情况下早于或晚于真实回弹 | **是** |
| 本轮就用 `invoke`/`handle` 把 `getState` 拉过来 | 一步到位 | 绕过契约新增通道；且会把 D3 的沉降窗口和状态轮询搅在一起 | 否（留待后续 ADR） |
| 用 `getDisplayNearestPoint()` 求显示器 | 一行代码 | 指针在显示器缝隙时给出错误显示器，钳制会跳屏 | 否 |
| `getAllDisplays()` 逐个求交取最大值（本方案 D6） | 缝隙场景仍确定 | 比一行代码多一点循环 | **是** |
| 第二实例时临时把主窗口 `focusable` 改 `true` 再 `focus()` | 行为直觉 | 已在 ADR 0003 被否决（闪烁、丢置顶、输入法异常） | 否 |
| `showInactive()` + 日志（本方案 D9） | 不碰窗口属性 | 用户看不到"抢焦点"的提示，只能靠托盘/日志 | **是** |

## 后果

**正面**

- `head_patted` 的判定权、拖拽的判定权、穿透的判定权**全部**落在主进程一处，渲染侧只提供事实（`hit`、`head`），符合 ADR 0002 的单一状态机意图。
- 探针通道只增加一个布尔，`§3.5` 与 `§6.3` 各改一行即可，不触事件名、不改状态集合、不新增通道。
- 探针乱序被"单探针在飞"从机制上消除，不需要新增关联 ID。
- 降级方向统一为"宁可多点一次，不可吞点击"，与 §12 已接受的残余缺陷同一取向。
- 掩膜三态把"首帧未就绪"从隐性缺陷变成显式分支，冷启动不再出现"第一下点击被吞"。

**负面 / 成本**

- `cmd:interactive` 载荷增加一个字段，所有消费方都要读版本；契约升到 1.2.0。
- `head` 的采信条件（坐标距离 ≤ 8 CSS px、新鲜度 ≤ 100ms）是一条经验规则，需在实现里写成常量并记录，否则后续对话容易各自发明阈值。
- 500ms 沉降窗口是估计值：回弹明显短于 500ms 时，拖拽后约半秒内点击仍会被窗口吞掉；长于 500ms 时，回弹尾部可能被穿透截断（视觉上无感）。
- 掩膜 `cold` 期间命中退化为矩形，冷启动最初一两百毫秒的判定精度下降。

**约束**

- `head` 字段只允许作为 `head_patted` 的触发条件；禁止用它决定穿透、决定拖拽、或反推手势。
- 4px / 250ms / 800ms 只允许由主进程基于 `cmd:drag` 原始事实判定；渲染侧不得计算任何阈值。
- `cmd:drag` 的载荷不得扩展为位移、速度或判定结果。
- 探针超时不得沿用上一次判定，必须按未命中处理。
- 不得为"精确回弹对齐"新增事件或修改 `render` 接口；只能走 `cmd:state` 的 ADR。
- 不得新增第二个光标轮询定时器（承接 ADR 0002）；掩膜 20Hz 定时器不属于光标轮询器，但必须在代码注释与 `MODULE_STATUS` 中写明区别。
- 不得使用 `getDisplayNearestPoint()` 做 D-7 钳制。
- 不得用 `invoke`/`handle` 承载 `getState`；该通道必须由 ADR 引入。
- 掩膜映射只允许 `src/shared/mask.ts` 一份实现。
- 页面缩放因子不得 ≠ 1。
- `MODULE_STATUS.md` 的 `shell` 节必须保留四条坑位：500ms 沉降窗口是估计值、`getState` 跨进程轮询未实现、`input: 'keyboard'` 本期不可达、`showInactive` 替代 `focus` 在 `focusable: false` 下是已知妥协。
