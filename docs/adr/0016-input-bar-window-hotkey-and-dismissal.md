# 0016. 输入条的窗口装配、热键降级与关闭归属

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-29 |
| 决策者 | 项目所有者 |
| 关联 | `CONTRACTS.md` §3.2（输入条行）、§3.5（`cmd:respond`）、§3.6 P-3、§6.3（`user_utterance`）、§7.2；ADR 0003（焦点策略）、ADR 0004 D8.2（输入条定位）；落地 MODULE_STATUS 的"输入条 preload 是否复用"待定项 |

## 背景

ADR 0003 已定"输入条必须是独立窗口、主窗口 `focusable` 恒为 false"，ADR 0004 D8.2 已定"放主窗口内容区顶边上方 8px，上方不足则下方 8px"。实现时仍有四个**规范未写、代码必须回答**的问题：

1. **Esc 与"点击桌面"由谁收窗。** 若新增 `cmd:input-cancel` 通道，属 §3.5 通道表扩充（必须 ADR）；若让渲染页 `window.close()`，窗口被销毁就违背 ADR 0003 §2 的"`show:false` 创建一次、反复 show/hide 复用"。而"收起"是窗口动作，渲染页没有这个权限。
2. **Enter 与输入法。** 中文组合输入期间按 Enter 是"确认候选词"，不是提交。若把提交也放到主进程（`before-input-event`），主进程就必须理解 IME 组合状态——它拿不到可靠的组合态。提交必须留在渲染页，但"提交后收窗"又要求主进程参与。
3. **热键冲突。** `globalShortcut.register()` 会返回 `false`（被占用）或抛错（加速键非法）。没有热键就没有文本入口，但"注册失败"不能变成"启动崩溃"，也不能假装成功。
4. **输入页 preload 是否复用主窗口 preload。** MODULE_STATUS 里这一项一直挂着"待定"。复用会把事件总线、探针、拖拽、语音命令全部暴露给一个只该"发一句话"的页面。

另有一条几何事实需要在决策里写死：主窗口是按模型取景包围盒**紧贴**出来的（422×720，脚底 = 内容区底边），"角色头顶之上"没有窗口内空间；窗口之外的上方正是输入条的位置。所以"字幕气泡在角色上方"与"输入条不与字幕重叠"这两条**不能同时**按字面实现——必须选一个明确的布局解释。

## 决策

### D1 独立窗口 + 独立最小 preload

1. 输入条是独立 `BrowserWindow`：`260 × 44`、`frame:false`、`transparent:false`、`alwaysOnTop`（层级 `screen-saver`）、`skipTaskbar`、`show:false` 复用、**不设 parent**、`movable:false`（位置由主进程跟随主窗口）。
2. **不复用主窗口 preload。** 新增 `src/preload/input.ts`，只暴露一个方法：`submit(text) → cmd:respond`。事件总线、`cmd:probe`、`cmd:drag`、`cmd:voice` 一律不暴露。
3. 输入页 `src/renderer/input/` 只含一个 `<input>`、一个发送按钮；CSP 为 `default-src 'none'; script-src 'self'; style-src 'self'`，并拒绝一切新窗口。

### D2 Enter 在渲染页；`cmd:respond` 由主进程收口

1. 渲染页处理 Enter：`event.isComposing || event.keyCode === 229` 时不提交（IME 候选确认）；否则 `preventDefault()` 后调 `window.petInput.submit(text)`。
2. `cmd:respond` 的接收方仍是主进程（shell）。主进程先校验**发送方**（只接受输入条窗口或主窗口渲染页），再校验文本（非空、≤500 字），随后：
   ```
   closeInputBar('submitted') → appBus.emit('user_utterance', { utteranceId, text, input:'hotkey' })
   ```
   即"关闭输入条"发生在事件之前，顺序与需求一致；`user_utterance` 的载荷、生产者、枚举值都不变（§6.3）。

### D3 Esc 与失焦在主进程；不新增通道、不发事件

1. Esc：主进程监听输入条 `webContents` 的 `before-input-event`，`key/code === 'Escape'` → `preventDefault()` → `hide()`。**不依赖渲染页**，因此输入页崩溃时 Esc 仍然有效。
2. 失焦：监听窗口 `blur` → `hide()`。隐藏本身会再触发一次 `blur`，实现里以"可见才处理"避免递归。
3. 收起只做窗口动作：**不聚焦主窗口、不改主窗口任何属性**（ADR 0003 §4），也不发任何事件（Esc 的语义是"取消"，不是"发生了一件事"）。
4. 不新增 `cmd:input-cancel` / `cmd:input-shown` 之类通道；提交沿用既有 `cmd:respond`。

### D4 热键三级降级

1. 默认 `Control+Shift+B`；注册失败（返回 false 或抛错）降级 `Control+Alt+B`，并在 `logs/pet.log` 打 WARN + 一行 `降级到备用热键`。
2. 两个都失败：记 ERROR，`accelerator = null`，**继续启动**（不抛、不退出）。此时文本入口不可用，但其余功能（规则/兜底/字幕/拖拽/摸头）不受影响。
3. 热键在 `app.ready` 之后、`shell.start()` 内注册；`shell.stop()` 时注销。热键回调是 toggle：可见则收起（`reason: hotkey-toggle`），不可见则打开并聚焦。

### D5 定位与跟随

1. 定位按 ADR 0004 D8.2：`y = content.y − 8 − 44`；若 `y < workArea.y` 则 `y = content.y + 8`。水平居中并钳制在工作区内。
2. 用 `getContentBounds()` 取内容区、`getDisplayMatching()` 取工作区（D-7 的"禁止 `getDisplayNearestPoint`"针对拖拽钳制的显示器缝隙，场景不同）。
3. 主窗口 `move` 时，若输入条可见则重新定位；**不新增定时器**。

### D6 与字幕气泡的位置关系（布局解释写死）

1. 字幕气泡保留在主窗口**内容区下沿**（上一轮已实现并验收的布局，`pointer-events:none`）。
2. 输入条永远在内容区顶边之外（正常）或顶边内 `8–52px`（贴顶下落分支）；字幕在窗口下沿，二者矩形不相交。
3. 选择"下沿"而不是"角色头顶"的理由：窗口按模型包围盒紧贴，头顶上方没有窗口内空白；真正的"头顶外部"位置被输入条占用。把字幕做成"窗口外、角色上方"需要**第三个窗口**，那是一次新的窗口与合成决策（另出 ADR），不在本轮。
4. 自检 `npm run selftest:input` 用矩形断言锁死这条关系（输入条打开时、以及回复显示时各断言一次）。

### D7 契约不变

本轮不新增通道、不新增事件、不新增状态/`intent`/`emotion`、不改 `RenderState`、不新增运行时依赖，因此 `CONTRACTS.md` 不动（仍是 1.4.0）。新增的 `shell.openInputBar()` / `closeInputBar()` / `inputBarDiagnostics()` / `hotkeySnapshot()` / `getInputBarWindow()` 是**非契约内部接口**（与既有 `notifySecondInstance()` 同类），只给热键回调与自检使用。

## 替代方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 打开输入条时把主窗口 `focusable` 临时改 true | 不用新窗口，代码最少 | Windows 上闪烁、丢置顶、输入法异常（§3.6 P-3），ADR 0003 已否决 | 否 |
| 新增 `cmd:input-cancel` 通道承载 Esc | 语义清晰 | 扩充 §3.5 通道表，需要契约 minor + ADR；且会把"窗口动作"变成可被页面伪造的消息 | 否 |
| 渲染页 `window.close()` 收窗 | 零通道 | 窗口被销毁，违背 `show:false` 复用；再次唤起要重建窗口与页面 | 否 |
| Esc 交给渲染页 keydown 后隐藏自身 | 无主进程参与 | 渲染页没有隐藏窗口的能力；页面崩溃时 Esc 失效 | 否 |
| 主进程用 `before-input-event` 同时处理 Enter + Esc（本方案只处理 Esc） | 一个地方收口 | 主进程拿不到 IME 组合态，会把"确认候选词"误判成提交 | 否 |
| 复用主窗口 preload 给输入页 | 少一个文件 | 输入页能发探针/拖拽/语音命令，攻击面与误用面扩大 | 否 |
| 独立最小 preload（本方案 D1） | 权限白名单式最小化 | 多一个 preload 与一条构建项 | **是** |
| 热键失败直接退出并提示用户 | 用户一定知道 | 桌宠其余功能全部不可用；崩溃/退出违背"优雅降级" | 否 |
| 两级降级 + 失败只记 ERROR（本方案 D4） | 最常见冲突能自愈；最坏只是没有文本入口 | 用户可能不知道热键没注册（只能看日志） | **是** |
| 字幕改到"角色头顶"（窗口内顶部） | 更像漫画气泡 | 与光环/头发重叠；贴顶下落时输入条正好压在字幕上（8–52px） | 否 |
| 字幕留在窗口下沿 + 输入条在顶边外（本方案 D6） | 两者几何上永久不相交；不遮挡面部 | 气泡压在脚部附近，观感一般 | **是** |

## 后果

**正面**

- 焦点策略完全落地：主窗口全程 `focusable:false`，输入条是唯一可聚焦窗口，关闭后焦点回到用户原来的应用。
- "谁负责收窗"只有一个答案（主进程），且 Esc 在渲染页崩溃时仍有效；未新增任何通道/事件。
- 热键冲突有确定的三级行为，最坏情况是"没有文本输入"，而不是"程序起不来"。
- 输入页的权限被压缩到一个方法，后续给输入条加功能（历史、@、快捷短语）必须显式扩 preload，不会顺手拿到角色页的通道。
- 输入条与字幕的不重叠从"注意别挡住"变成"几何上不可能相交 + 自检断言"。

**负面 / 成本**

- 多一个窗口、一个 preload、一个渲染页与一条构建项。
- 字幕仍在脚部附近：这是"窗口紧贴模型"的直接结果，观感不如头顶气泡；要做头顶外部气泡需要第三个窗口（另出 ADR）。
- 热键注册失败只有日志，没有托盘提示（托盘仍未实现）。
- `movable:false` 意味着拖动输入条无效，用户若想把它挪开会被"弹回"——这是刻意的（位置属于主窗口）。

**约束**

- 禁止调用 `mainWindow.setFocusable(true)`；禁止给输入条设 `parent`。
- 禁止为 Esc/失焦新增通道或事件；禁止让渲染页自己关闭窗口。
- 禁止在输入页暴露除 `submit(text)` 之外的任何能力。
- 禁止把 Enter 的提交判定移到主进程（IME 组合态只在渲染页可靠）。
- 禁止把字幕移到与输入条可能相交的区域（贴顶分支的 `8–52px`）。
- 热键注册失败不得抛出、不得退出；不得自动重试注册（避免与占用方互相抢）。
- 输入条不得承载角色渲染、`getState()` 轮询或任何模块逻辑。
