| 项 | 值 |

## 背景

阶段 4.5 的 render 只有两条常驻通道：程序化呼吸（`modelRoot` 的缩放）与视线（每帧直接写 `Bip001 Head` / `eye_L` / `eye_R` 的旋转）。资产里 44 段骨骼动画一直没敢用，原因是它们会与视线抢同一批骨骼：实测 `CH0335_Normal_Idle` 的 192 条通道里有 46 条平移、135 条旋转，**明确包含 `Bip001 Head`、`Bip001 eye_L`、`Bip001 eye_R`**。如果按最直觉的方式接进去，会立刻撞上三个问题：

1. **覆盖方向不定。** `AnimationMixer.update()` 每帧重写被驱动骨骼的 `quaternion`；`gaze.ts` 每帧也重写同一批骨骼，并且它的基底是**创建时快照的绑定姿态**（`bone.quaternion.clone()`）。结果不是"动画把视线盖掉"，而是"视线把动画盖掉"——Idle 的头颈动作会被完全抹平，同时如果反过来调换顺序，视线又会被动画抹平，回到"眼神死板"。
2. **HFSM 没有落地载体。** §4.1 的三层状态（`idle` / `walking`、`speaking` / `reacting`、`dragged`）目前只体现在 `getState()` 的常量里；没有任何一个地方真正拥有"现在该播哪段动画"的决定权。
3. **拖拽与摸头没有表现。** `drag_started` 只暂停了掩膜采集，角色在窗口里仍是站姿；`head_patted` 没有任何消费者。

同时有四条硬约束不能破：状态集合严格按 §4.1（不加第六个名字）、`RenderState` 字段不得增删（§7.1）、口型通道优先级最高（§5.2，`reacting`/`dragged` 都不得降低口型权重）、不得引入任何按次计费依赖。

## 决策

### D1 每帧骨骼更新顺序（唯一顺序）

渲染循环每帧固定六步，顺序不得调换：

| 步 | 动作 | 写什么 |
|---|---|---|
| 1 | `AnimationMixer.update(dt)` | 被 clip 驱动的节点/骨骼的平移、旋转、缩放 |
| 2 | 骨骼仲裁 `beginFrame()` | 记录"本帧动画产出的本地旋转"（见 D2），并把本帧的叠加量清零 |
| 3 | 视线通道叠加 | `Bip001 Head` / `eye_L` / `eye_R` 的 yaw、pitch（父空间绕世界轴，**加法**） |
| 4 | 反应通道叠加（`pat_react` 等） | 头部的 pitch（后仰）与 roll（侧倾），按权重缩放 |
| 5 | 骨骼仲裁 `endFrame()` | 每根受控骨骼**只写一次**最终四元数 |
| 6 | Physics 层根变换 | `animationRoot` 的整体摇摆/位移（不写骨骼） |

`renderer.render()` 在 6 之后。`AnimationMixer.update()` 只允许出现在第 1 步，事件回调里禁止 `update`（否则同一帧内会被更新两次，交叉淡入的权重会跳变）。

### D2 视线覆盖：加法覆盖 + "写回检测/还原"，禁止快照绑定姿态

1. 视线**不再持有绑定姿态基底**。`gaze.ts` 每帧只计算 yaw/pitch，通过 `boneArbiter.add(bone, yaw, pitch, roll)` 交给仲裁器；最终旋转由仲裁器一次写成 `offsetQ × animatedLocalQ`（offset 在骨骼父空间，轴由父骨骼世界四元数反解，避免依赖 3ds Max 导出的局部轴朝向）。
2. 因为 three 的 `AnimationMixer` **没有骨骼级 mask**，"哪些骨骼本帧被动画写过"只能在写回时判断。仲裁器对每根骨骼保存三个量：上一帧的动画基底 `prevBase`、上一帧我们写出的最终值 `applied`：
   - 若 `beginFrame()` 时 `bone.quaternion ≈ applied`（说明本帧 mixer **没有**重写它）→ 基底沿用 `prevBase`，避免把上一帧的视线偏移当成动画数据累加；
   - 否则（mixer 重写了）→ 基底取当前值，即本帧动画的真实产物。
3. 受控骨骼集合固定为 `head` / `eyeL` / `eyeR`（ADR 0009 D6 的关键骨骼）。**只有仲裁器可以写这三根骨骼的 `quaternion`**，`gaze.ts`、pat 反应、未来的口型模块都只能 `add` 偏移。
4. 视线幅度、平滑、5s 微动参数保持阶段 4.5 的口径（ADR 0010 D1），只把"写旋转"换成"交偏移"。

### D3 HFSM 如何控制 AnimationMixer

1. 动作集合（按名字选择，带模式降级；选择结果与降级原因写日志）：

   | 用途 | 首选片段 | 降级模式 | 循环 |
   |---|---|---|---|
   | Base 待机 | `CH0335_Cafe_Idle` | `/cafe[_\s-]?idle/i` → `/normal[_\s-]?idle/i` → `/idle/i` | `LoopRepeat` |
   | Physics 悬空 | `CH0335_Carrier_Idle` | `/carrier[_\s-]?idle/i` → `/pickup/i` → `/panic/i` | `LoopRepeat` |
   | 行走（本轮只识别不启用） | `CH0335_Move_Ing` | `/move[_\s-]?ing/i` | `LoopRepeat` |

   **为什么不是 `CH0335_Normal_Idle`**（实测）：它是战斗侧身待机，根骨 `Bip001` 的旋转在绑定姿态 `-90°` 的基础上再转约 `-87°`（四元数 `z≈0.9994, w≈-0.0288`），播放后角色整身侧对镜头；`CH0335_Cafe_Idle` 的根骨旋转是 `-98.6°`（≈绑定 + 8.6°），是面向玩家的大厅待机。桌面宠物需要正面待机，因此首选 `Cafe_Idle`，`Normal_Idle` 只作为降级候选并在日志里保留识别结果（44 段名称全部打印）。

   `CH0335_Vital_Panic`（挣扎）、`CH0335_Formation_Pickup`（被拎起）在本轮只作为 `held` 的降级候选，不单独驱动。
2. 切换只走 `crossFadeFrom(prev, seconds, false)`：Base ↔ Physics 使用 0.25s（进入拖拽）/ 0.3s（松手回 Idle）。**不给整身动作做"叠加"**：Overlay 的一次性反应只作用于通道（D2 的偏移 + 根变换），不做第二个整身 action，否则会违反 H-1（完整身体动画打断语音）。
3. Physics 层的"悬空"表现由三件事合成（都不写骨骼）：淡出 Base（Idle 的 Y 轴位移随之停止）、抬升 `animationRoot` 18px（220ms 斜坡）、整体摇摆 ±0.05 rad（周期 1.6s，松手后 12/s 指数衰减回 0）。松手只回 Idle，不做真实回弹（下一轮）。
3. 状态迁移（全部来自 §4.1，未新增任何状态名）：

   | 输入 | 迁移 | 触发 |
   |---|---|---|
   | `speech_started` | Overlay = `speaking`，记 `speakingUtteranceId` | 事件（`voice` 未实现，本轮只跟随） |
   | `speech_ended` | Overlay 清 `speaking` | 事件 |
   | `head_patted` | Overlay 加 `reacting`（一次性，1.1s） | 事件 |
   | `handleIntent(intent)`，`intent ∈ {pat_react, happy_hop, nod, shake_head, tilt_head}` | Overlay 加 `reacting` | 命令（§4.1 列出的进 `reacting` 的 intent 全集） |
   | `drag_started` | Physics = `dragged`，Base 动作 crossFade → `held` | 事件（render 不得自行进出） |
   | `drag_released` | Physics 退出，crossFade → `idle` | 事件 |

4. `getState().overlay` 是**单字段投影**：`speaking` 与 `reacting` 可同时存在（§5.1），但 §7.1 只有一个 `overlay` 字段，因此按优先级投影为 `speaking` > `reacting` > `null`；两者并存的事实通过内部诊断暴露（不新增字段）。
5. `walking` 本轮不实现（Base 恒为 `idle`），但枚举值保留；`idle` 的退出条件在代码里不成立，不会出现"自行进入 walking"的隐藏行为。

### D4 根动作与地面校正

1. 模型自带动画带 `Bip001` 的根平移，实测幅度极小（Idle 的 Y 分量 0～2e-5、Z 0.0031；`Carrier_Idle` 的 Z 0.0034；`Formation_Pickup` 最大 0.0013 横向），**没有持续的水平漂移**，因此不裁通道、不改 track。
2. 但姿态与绑定姿态不同：Idle 在第 0 帧把 `Bip001` 从绑定的 `y=-0.00038` 提到约 `0`。为避免"悬空站立"，加载后按 Idle 姿态做**一次**CPU 蒙皮采样（每网格最多 4096 个顶点，取可见网格的最低点，采样值经 `root.worldToLocal` 换回模型单位），把最低点对齐内容区底边；差值写诊断。该校正只在加载与 `resize` 后重算，不逐帧执行。实测 `Cafe_Idle` 姿态的最低点与绑定姿态只差 `-0.2px`（`Cafe_Idle` 的站姿本来就贴地），校正量因此很小，但机制必须留着——换模型/换片段时它就是兜底。
3. 拖拽期间**不**重新对齐地面：悬空是 Physics 层的表现，回弹留到下一轮。

### D5 配件隐藏 `HIDE_ATTACHMENTS`

1. 新增配置 `HIDE_ATTACHMENTS`（默认 `(weapon|prop|brush|outline)`，环境变量 `PET_HIDE_ATTACHMENTS` 覆盖）。语义是"装配模型时把不参与角色的部件设为不可见"。
2. 只做 `mesh.visible = false`，**不删除节点、不改材质、不改几何**（可逆、可配置，不破坏动画绑定与 GLTF 的节点表）。
3. 默认值等于取景排除正则（ADR 0009 D3），并在 `asset-config` 里保证"未显式覆盖时二者同源"；若显式覆盖成不同的正则，记一条 WARN，且**隐藏集合同样不参与渲染侧取景**（主进程仍只按 `PET_FRAME_EXCLUDE` 定窗口，两者不同属于显式配置风险）。
4. 被隐藏的网格名进诊断（`hiddenMeshes`）与启动日志。

### D6 `pat_react`：程序化，无专用摸头动画

1. 资产里没有摸头/被摸头片段：`CH0335_Cafe_Reaction`（10.75s）是整身演出，`CH0335_Formation_Pickup`（14s）是搬运流程，二者都会抢身体/口型通道，本轮**不用**。
2. 采用程序化合成（三个通道同时作用，时长 1.1s，`sin(π·p)` 包络）：
   - 头部：后仰 `-0.3 rad`（≈17°）+ 侧倾 `0.08 rad`（经 D2 的仲裁器写 `Bip001 Head`）；
   - 身体：`animationRoot` 前倾 `0.05 rad`（不改变脚底锚点）；
   - 表情：嘴型图集切到"shy"帧（`PAT_MOUTH_FRAME = 4`，走 ADR 0010 D2 的贴图合成管线），结束时回到第 0 帧。
3. **权重上限**：`speaking` 期间反应权重 `≤ 0.4`（`PAT_SPEAKING_WEIGHT_CAP`），且**不触碰嘴型贴图**（§5.2 口型通道优先级最高，§5.3 "说话时被摸头"）；非说话时权重 1.0。
4. `emotion` 在反应期间投影为 `shy`（§4.5 "常与 `pat_react` 搭配"），结束后回到 `intent_resolved` 带来的值；不新增 emotion 值。

### D7 当前动作名的暴露位置

`RenderState`（§7.1）**不得新增字段**，因此"当前动作名"不进 `getState()`，而是走既有的内部诊断通道 `window.petModel.getDiagnostics().animation`（与 ADR 0009 D7.2 对骨骼/包围盒的处理一致），并在动作切换时打一行日志。若后续确需让 `shell`/`orchestrator` 读到动作名，必须走契约 minor 升版 + ADR，不得在代码里私加字段。

### D8 程序化呼吸退役

Base 层的呼吸由 Idle 动画（`CH0335_Cafe_Idle`，降级 `CH0335_Normal_Idle`）承担（§5.1 "呼吸属于层内常驻通道，不是状态"），删除阶段 4.5 的 `modelRoot` 缩放呼吸：同一件事不再有两份驱动，避免"缩放呼吸 × 骨骼呼吸"叠加变形。占位胶囊体（模型缺失）不再呼吸，只保留反应位移/缩放。

## 替代方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 继续不用自带动画，只加程序化呼吸/眨眼 | 零冲突 | 44 段资产闲置；姿态没有重量感；"眼神死板"问题只是被回避 | 否 |
| 让 `AnimationMixer` 独占骨骼，视线只写眼球 | 实现最简单 | 动画把头也写死，视线幅度受限；`eye_L/R` 同样在 Idle 通道里，仍会被覆盖 | 否 |
| 用 `AnimationMixer` 的骨骼级 mask 让动画不写 head/eye | 语义最干净 | three 没有骨骼级 mask，只能重建 track 列表；换模型/换片段都要重算，且丢头颈动画 | 否（记入后续可选优化） |
| 视线先写、动画后写（把 D1 顺序反过来） | 代码几乎不用改 | 动画直接覆盖视线，正是用户明确禁止的"眼神死板" | 否 |
| 视线继续用绑定姿态做基底 | 复用现有实现 | 一旦播动画，头颈动画被抹平；且"基底"本身就是错的 | 否 |
| 每帧直接把偏移乘到当前四元数上，不做写回检测 | 少一个分支 | 未被动画驱动的骨骼会逐帧累积偏移，几十秒后头会歪死 | 否 |
| 加法覆盖 + 写回检测/还原（本方案 D2） | 动画保留、视线保留、单写者、无累积 | 每根骨骼多存两个四元数、每帧一次点积比较 | **是** |
| 摸头播 `Cafe_Reaction`（10.75s 整身） | 现成动作、表现力强 | 抢身体通道，与 `speaking` 的"≤0.4 权重"要求直接冲突 | 否 |
| 摸头用骨骼缩放/闭眼骨 | 直观 | 无眼睑骨、无 blendshape；缩放眼球已被 ADR 0010 证伪 | 否 |
| 程序化摸头 + 嘴型贴图（本方案 D6） | 不抢口型、权重可控、与现有贴图管线同源 | 表现力弱于专门动画，靠 `shy` 嘴型补 | **是** |
| 配件直接从场景移除 | 最干净 | 不可逆、破坏节点表、动画 track 指向的节点可能缺失 | 否 |
| `visible = false`（本方案 D5） | 可逆、可配置、不动材质 | 仍占用少量内存（不渲染） | **是** |
| 把动作名加进 `RenderState` | 消费方直接可读 | 违反 §7.1 字段固定；本轮明确不改契约 | 否（走诊断，D7） |
| 呼吸继续程序化 + 同时播 Idle | 不丢现有代码 | 双重呼吸，缩放与骨骼动作叠加变形 | 否 |

## 后果

**正面**

- 44 段动画终于可用，Base 层的"活着"由资产本身承担；视线与动画第一次有了**明确的仲裁顺序**，两边都不再被对方抹掉。
- HFSM 有了唯一的所有者：动作切换、Overlay 投影、Physics 接管都在一个纯逻辑模块里，可以脱离 WebGL 单测。
- 摸头、拖拽都有可截图的可见表现，且都不碰口型通道，为阶段 5 的语音留好了位置。
- 配件隐藏与取景排除同源，窗口尺寸不再被武器/道具撑宽，也不用删除模型部件。
- 没有新增状态名、事件名、`intent`/`emotion` 值、依赖或计费路径；`CONTRACTS.md` 未改。

**负面 / 成本**

- 仲裁器为每根受控骨骼多存两个四元数并做一次比较，属于可忽略的开销；但"哪些骨骼被动画驱动"是**推断**而非事实，极端情况下（动画恰好写出与我们上一帧完全相同的值）会判断错一次，下一帧自愈。
- `getState()` 看不到动作名（D7），调试要读日志或内部诊断；这是契约字段固定的直接代价。
- 地面校正是一次性 CPU 蒙皮采样（每网格 ≤4096 顶点），冷启动多几毫秒；姿态变化大的片段（如 `Formation_Pickup`）不参与校正。
- 摸头是合成动作，近看不如专门动画自然；`shy` 嘴型帧是资产相关标定，换图集要重新选帧。
- 拖拽仍无真实回弹（下一轮），松手是"淡回 Idle"，快速甩动会有轻微跳变。

**约束**

- 只有 `bone-arbiter` 可以写 `head` / `eyeL` / `eyeR` 的 `quaternion`；其他模块只能提交偏移。
- `AnimationMixer.update()` 只允许在渲染循环第 1 步调用；事件回调里禁止更新 mixer。
- 禁止把整身 overlay 动画叠加到 Base 上（H-1 / H-2）；Overlay 只作用于通道。
- 禁止新增状态名（H-3）；`dragged` / `speaking` 只能由事件进入或退出（H-4）。
- `speaking` 期间 `pat_react` 权重不得超过 0.4，且不得改写嘴型贴图。
- `HIDE_ATTACHMENTS` 只允许 `visible = false`，不得删除节点或改材质；默认必须与取景排除一致。
- 拖拽期间不得复位地面校正；回弹不得以新增事件/通道实现（ADR 0004 D3 仍然有效）。
- 不得为接入动画新增运行时依赖、事件、IPC 通道或 `RenderState` 字段。
