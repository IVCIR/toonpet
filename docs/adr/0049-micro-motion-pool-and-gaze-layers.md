# 0049. 状态微动作池（sitting / idle）与视线三级阻尼

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-11-05 |
| 决策者 | 项目所有者（"sitting 和 idle 的微动作要有随机变化，不是固定循环""眼先动、头慢半拍"） |
| 关联 | 契约 §7.3（render 表现规则）；ADR 0014（骨骼仲裁）、ADR 0010（视线微动替代眨眼）、ADR 0023 / 0041（待机轮换与空闲小动作）、ADR 0044 / 0045（坐姿活体微动）、ADR 0039 D2（不为单个反应手写骨骼姿态）、ADR 0046 D1（眼球基底覆写）、ADR 0047 / 0048（头部姿态与微调） |

## 背景

两件事在优化清单上，且都**不新增状态、不新增片段**：

1. **固定循环**：`sitting` 的活感一直是"呼吸 + 自主张望 + 晃腿"三件套，`idle` 是"四段待机轮换 + 45–95s 一次官方害羞片段"。节拍固定、组合固定，看几分钟就能数出来。
   参考项目 `codex-pet`（Agent 状态可视化）在"状态 → 表演"的映射上有一个值得借鉴的做法：**同一个状态维护一个表情/小动作池**，每次从池里抽一个，而不是把状态绑死到一段循环。
   本项目不是 Agent 可视化（方向是 3D 角色陪伴 + 物理交互），只借"池 + 随机抽签"这一层。

2. **视线是单层平滑**：`gaze.ts` 只有一个 `SMOOTHING_PER_SECOND = 12` 同时作用在头与眼上
   （眼球只是在其上叠 `× 0.35` 的额外量）。于是"眼先动、头慢半拍"在画面上不存在——
   头和眼是同一个时间常数，躯干完全不动。真机上读起来像"整块头在匀速转"。

## 决策

### D1 微动作池（sitting / idle）

- **条目与间隔集中在 `shared/constants.ts`**：`IDLE_MICRO_POOL`、`SIT_MICRO_POOL`、
  `MICRO_POOL_MIN_MS = 15_000`、`MICRO_POOL_MAX_MS = 30_000`、
  `MICRO_POOL_TRANSITION_RATE = 3.0`。条目只写 `kind` 与抽签权重，不写骨骼名。
- **调度器**是纯逻辑 `renderer/render/micro-pool.ts`（不引用 three、不读时钟）：
  - 每 15–30s 随机抽一个条目（**排除当前条目**，保证每次都是可见的变化）；
  - 每个条目维护一个 0..1 的权重，向"当前条目 = 1 / 其余 = 0"做
    `1 - e^{-rate·dt}` 的指数逼近；
  - 权重之和在交叉时保持 ≈1（所有条目用同一个 α），所以换条目是**交叉淡入淡出**，
    不是瞬切；
  - 上下文不成立时（拖拽 / 行走 / 说话 / 一次性演出 / 坐姿接近阶段 / 空闲小动作），
    权重平滑归零并暂停抽签；回到上下文后**从 15–30s 重新计时**（不在回来的一瞬间就换）。
- **sitting 池**（`SIT_MICRO_POOL`，权重 3:1:1）：
  | 条目 | 表现 | 实现 |
  |---|---|---|
  | `legs` | 现有晃腿（ADR 0044 / 0045） | 腿骨旋转 × 1 |
  | `hands` | 低头看手 | 头/颈/眼向下（+0.17rad + 偏向手）、躯干微前倾、**晃腿停下**、随机张望淡出 |
  | `far` | 抬头看远处 | 头/眼抬起（-0.15rad + 偏一侧）、躯干微后仰、晃腿放慢到三成 |
  - 为什么 `hands` 不做字面"托腮"：本资产没有 IK，把手抬到下巴要靠上肢三根骨骼手调，
    既可能穿模也违反 ADR 0039 D2 的教训。坐姿停帧时手本来就放在膝上，
    **"低头看手"是需求里写出的同义选项**，且只用头/颈/眼，零穿模风险。
- **idle 池**（`IDLE_MICRO_POOL`，权重 3:1）：
  | 条目 | 表现 |
  |---|---|
  | `browse` | 现有待机（四段轮换 + 光标视线），不动一根骨头 |
  | `headTilt` | 偶尔歪头：头骨 roll 0.14rad + yaw 0.06rad，颈分担 45%（歪来自整条脖子） |
  - **不污染站立姿态**：`captureIdleUpperPose()`（ADR 0048）在歪头权重 > 0.001 时**不采样**，
    否则坐姿会照抄一个"歪着的头"。
- 池**不是**状态：`getState()` 的 `base` / `overlay` / `physics` 完全不变；不新增事件、IPC、
  `RenderState` 字段；不新增动画片段、不引入 Live2D / 精灵图。
- 诊断只进内部：`RenderDiagnostics.microPool.{idle,sit}`（`active` / `weights` / `switches` /
  `nextSwitchInMs` / `forced`），另有 `window.diagnostics.microPool()`（极轻）与
  `forceMicroPool()` / `setMicroPoolInterval()` 供自检取证与压缩时序。

### D2 视线三级阻尼

- 三层独立一阶阻尼，参数集中在 `shared/constants.ts`：
  | 层 | 骨骼 | 刚度（1/s） | 目标 |
  |---|---|---|---|
  | 眼球 | `Bip001 eye_L/R` | **12** | `(目标 − 当前头) × 0.45 + 目标 × 0.35`（夹 ±0.45rad） |
  | 头部 | `Bip001 Head` | **8** | 光标 / idle 目标（±0.32 / ±0.2rad） |
  | 躯干 | `Bip001 Spine1` | **4** | `sign(yaw) × max(0, |yaw| − 0.08) × 0.18`（**只在偏航超阈值时**跟，最大 0.043rad） |
- **为什么眼球还要"领先份额"**：只把眼球的刚度调快不够——它自己的目标量只有
  `0.35 × 目标`（约 0.11rad），头部要走到 0.32rad，画面上"先动"的仍然是头。
  让眼球先承担"头还没到的那一截"（`GAZE_EYE_LEAD_SHARE = 0.45`），总朝向在前 100ms
  就能扫过大半；头部追上后，眼球自动回落到常驻的 `× 0.35`（= 自然的"眼球回中"）。
- **光标离开跟随范围**（超过 `GAZE_CURSOR_HOLD_MS = 150ms` 没有新的 `cmd:probe`）：
  目标先**保持 150ms**，之后三层改用更慢的 `GAZE_RELEASE_STIFFNESS = 3.0` 缓出回正，
  **不得**立即弹回。静默超过 `GAZE_CURSOR_IDLE_TIMEOUT_MS = 1500ms` 才进入 idle 随机
  微动（每 5s 换向，替代眨眼，ADR 0010 D1 不变）。
- 判据（自检实测）：光标从正中跳到右侧后，到 90% 终值的时刻为
  **眼球 32ms / 头部 268ms / 躯干 499ms**——三层的时间差在画面上是肉眼可见的。

## 真机第二轮修订（2026-11-05）

真机实测提出三个体验问题，均在本 ADR 内修订（**不新增状态/事件/IPC**）：

### D4 躯干跟随：不是被覆盖，是幅度太小

- 排查结论：`BoneArbiter` 写入的 Spine1 旋转**没有被覆盖**（骨骼级诊断实测
  `final · base⁻¹` 绕世界 Y 的分量 = 提交量，`axisY = 1.000`）。
  问题是第一版的死区/份额：阈值 0.08rad、份额 0.18 → 头部偏航 0.244rad 时
  躯干只跟 **0.0295rad（1.7°）**，在 720px 高的 chibi 躯干上肉眼确实看不出来。
- 修订：阈值 **0.08 → 0.05rad**、份额 **0.18 → 0.35**。
  头部 0.244rad 时躯干跟 **0.0666rad（3.82°）**，最大 0.32rad 时跟 **0.0945rad（5.4°）**。
- 新增**骨骼级诊断** `GazeBoneDiagnostics`（`RenderDiagnostics.gaze.spineBone` /
  `window.diagnostics.gaze().spineBone`）：从 `spine1.quaternion · animationBase(spine1)⁻¹`
  反解本帧实际写入的旋转，投影到世界 Y，输出 `spineYawRad` / `spineYawDeg` / `axisY` /
  `submittedYawRad`。这就是"Spine1 的实时 rotation.y"，可用来区分"没提交"与"被覆盖"。
- 自检实测：`spineYawRad = 0.0665–0.0666`、`spineYawDeg = 3.81–3.82`、`axisY = 1`、
  `submittedYawRad = 0.0665–0.0666`（完全一致）。

### D5 `headTilt` 生命周期：必须有"进入"和"退出"

- 问题：池第一版把 `headTilt` 当"当前主打条目"一直保持到下一次抽签（15–30s），
  真机观感就是"歪头之后一直歪着"。
- 修订：`MicroPoolEntry` 新增 `holdMinMs/holdMaxMs`。**默认条目**（idle 的 `browse`、
  sitting 的 `legs`，= 池里的第一项）不设 hold；**非默认条目**到时后自动回到默认条目，
  权重按 `MICRO_POOL_TRANSITION_RATE` 指数衰减到 0：
  - `headTilt`：**3000–5000ms**；
  - `hands`：4000–7000ms；`far`：5000–8000ms（坐姿变奏也不该一直保持）。
- 补充语义：
  - 回正**不算**一次随机抽签，`nextSwitchAt` 不变（下一次抽签仍按 15–30s 的节奏）；
  - 上下文失效（进入坐姿 / 拖拽 / 一次性演出）时，非默认条目**立即**回默认，
    不会把"歪着的头"带进坐姿；
  - `force()` 是取证开关，**强制期间忽略 hold**；解除强制时回到默认条目；
  - `MicroPoolSnapshot` 新增 `releases` 与 `holdRemainingMs`，自检/诊断可读。
- 自检实测：`headTilt` 的 `headBase.roll = 0.1388rad`；解除后 1.2s 内
  `roll = 0.0036rad`、`releases = 1`、`headTilt` 权重降到 0.026（平滑衰减中）。
- 生产常量模拟（20s 抽签、随机源固定 0）：`t=20000ms` 抽到 `headTilt`
  （`holdRemaining=3000ms`）→ `t=23000ms` 自动回 `browse`（`releases=1`、`switches` 仍为 1）；
  权重 `0.741`（回正第一拍）→ `0.037`（+1s）→ `0.008`（+1.5s）。

### D6 坐姿张望：从"雷达扫描"改成"发呆看风景"

- 换向保持：**2.2–4.2s → 5–9s**；
- 过渡：`easeInOutCubic` **220–420ms → 800–1200ms**；
- 到位后**完全静止**：显式常量 `SIT_GAZE_STILL_MIN_MS = 2000`，
  调度取 `max(2000, 本次 hold)`，所以未来把 hold 调小也破不了"≥2s 静止"的下限。
- 自检实测：11.6s 观测窗口内看到 2 个目标，最长连续静止 **6.1–8.9s**（三轮）；
  头骨摆动幅度 0.38–0.46rad（yaw + pitch）。
- 频率与幅度都只是"放缓"：目标范围（±0.36 / +0.06 / −0.22）与抬头偏好不变。

### D7 顺带修掉反应"到期但仍挡新反应"的一帧边界

- 现象：自检"说话时被摸头"偶发 `pat.active=false`，但日志里明明有
  `pat_react（intent 命令）→ reacting（仅表情：speaking）`。
- 根因：`hfsm.intent('pat_react')` 只用 `isPatReaction(reaction)` 判断"已有摸头反应"，
  而 `reaction` 要等下一帧 `tick()` 才清空。**刚到期的这一帧**里
  `pat.active=false`（按时间算）但 `reaction` 仍在，于是新反应被一条已播完的旧反应拒掉。
- 修法：判断里加上 `now - reaction.startedAt < reaction.durationMs`（未到期才拒绝）。
  `hfsm.test.ts` 新增 1 条："过期反应不挡新 pat_react、未到期仍拒绝"。
- 这与本轮的视线/池无关，是排查"说话时被摸头"假失败时顺带发现的真 bug。

### D8 拖拽接管时把"半途的第三个 action"一并淡出

- 现象：自检"拖拽：Base 的 Idle 已淡出"偶发失败，`Cafe_Idle` 在拖拽中仍有 **0.52** 权重。
- 根因：`fadeTo` 只对 `currentAction` 调 `crossFadeFrom`。待机轮换的 0.8s 淡入如果
  在拖拽那一拍还在半途，`Cafe_Idle` 既不是 current、也不在淡出队列里，权重就冻结了；
  结果悬空姿态上真的叠了一层站姿（不只是断言的假失败）。
- 修法：`animation-controller` 维护 `actionRegistry`（基础槽位 + 语义角色去重），
  每次 `fadeTo` 把"除目标与上一个 action 之外、仍有权的 action"一并 `fadeOut`。
  单测 `animation-controller` +1（`Cafe_Idle` 最终 <0.1）。
- 这是排查假失败时发现的真 bug，与视线/池无关，但属于同一轮"真机体验"修复。

## 替代方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 固定循环里插入固定变奏（每 N 秒循环 A→B→C） | 实现最简单 | 仍是可数的节拍，没有"偶尔"的意味 | 否 |
| 用官方片段做 sitting 变奏 | 天然可信 | 资产里没有"抬头看远处 / 低头看手"的坐姿片段；ADR 0045 D1 已删除无片段支撑的程序化大动作 | 否 |
| 池只记"当前条目"，由调用方自己淡入淡出 | 调度器更小 | 每个调用点都要重复维护上一帧与包络，容易写成瞬切 | 否（权重放在池里） |
| sitting 的字面"托腮"（抬手臂） | 更贴近需求原词 | 无 IK、手会穿脸/穿发；违反 ADR 0039 D2 的"不手写姿态"教训 | 否（取"低头看手"） |
| 视线保持单层、只调大/调小 `SMOOTHING` | 一行改动 | 头与眼仍然同步，"眼先动"不存在；躯干仍然完全不动 | 否 |
| 眼球刚性跟随目标（`eye = target − head`） | 时间差最明显 | 头部追上后眼球会一直偏着（斜视），不符合"眼球回中" | 否（用领先份额） |
| 三层都用同一个刚度、只改幅度 | 不会过冲 | 没有"慢半拍"，正是本轮要修的东西 | 否 |

## 后果

**正面**

- `sitting` 与 `idle` 的微动作从"固定循环"变成"每隔 15–30s 抽一次、平滑交叉"，
  且每一种变奏都只用现有骨骼（头 / 颈 / 脊柱 / 腿），不依赖新片段。
- 视线有了明确的"眼 → 头 → 躯干"时间阶梯；光标离开时不再瞬间回弹。
- 池与阻尼参数全部集中在 `shared/constants.ts`，调参不需要碰渲染代码。

**负面 / 成本**

- 多了一层调度状态（权重表）与两个内部诊断接口；`getDiagnostics()` 的 `microPool` 块
  会随帧变化（但不进 `RenderState`）。
- 自检为了稳定命中 15–30s 的随机切换，必须用 `setMicroPoolInterval()` 压缩时序；
  生产路径不调用它（默认仍是 15–30s）。
- `headTilt` / `hands` / `far` 的幅度是**一次标定**：换模型或换窗口高度要人眼复核
  （`sit-micro-hands.png` / `sit-micro-far.png` 是当前证据）。

**约束**

- 不新增状态名、事件、IPC 通道、`RenderState` 字段；池只活在 `render` 内部。
- 不新增动画片段、不引入 Live2D / 精灵图、不产生任何按次计费调用。
- 池的过渡必须是交叉淡入淡出（权重指数插值），**禁止**瞬切；
  回正必须经过 150ms 保持窗口，**禁止** `target = 0` 后立刻把当前值清零。
- 眼球偏移必须夹在 ±0.45rad 内，且 `bone_eye_D_*` 仍然一个通道都不写（ADR 0046 D2）。
