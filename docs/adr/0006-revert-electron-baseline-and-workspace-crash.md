# 0006. 撤回 Electron 44 基线，恢复 33.4.11，并记录"工作区目录导致 Chromium 崩溃"

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-10-27 |
| 决策者 | 项目所有者 |
| 关联 | 替代 #0005；`CONTRACTS.md` §3.1、§3.6；`docs/MODULE_STATUS.md` |

## 背景

ADR 0005 依据三个观察把 Electron 基线从 `33.4.11` 升到了 `44.7.0`：Electron 33/38 在本机启动即崩、同机的 DeepSeek Harness（Electron 44.7.0）运行正常。后续定位发现**归因错误**：

1. 同一份工程、同一份二进制，放在 `D:\petapp`、`D:\pettest`、`C:\Users\<user>\pet-test`、`D:\aa3dpet2`、`D:\acl-probe` 都能正常启动：`--version` 退出码 0，完整自检 exit 0，`logs/pet.log`、`logs/boot.log`、`dist/selftest/window.png` 三件产物齐全。
2. 只要可执行文件位于 **`D:\aa3dpet`（本会话工作区）** 之下，就固定以 `0x80000003` 在 Chromium 初始化阶段退出（约 30–40ms，主进程 JS 未执行）。`D:\aa3dpet\.tmp-test` 这种一层子目录同样失败；把 DSH 自己的 `DeepSeek Harness.exe` 复制进该目录也失败——**与二进制无关**。
3. 已逐项排除：ACL（把工作区 DACL 原样套到 `D:\acl-probe` 后仍正常）、强制完整性标签（所有目录均无 ML）、代码签名（官方包未签名；已签名的 DSH 包放进工作区照样崩）、Electron 版本（33/38/44 在工作区内一致失败，33/44 在工作区外一致成功）、`TEMP` 重定向、Job 对象 UI 限制（`UIRestrictionsClass=0x0`）、系统 Exploit Protection（全部 `NOTSET`）、第三方杀软（无）、`AppInit_DLLs`（空）、Smart App Control（关闭）。

## 决策

1. **Electron 基线恢复为精确 `33.4.11`**，撤销 ADR 0005 的升级。工作区外实测通过：窗口 `480×720`、`isAlwaysOnTop=true`、`isFocusable=false`、`isResizable=false`、`zoomFactor=1`、底边居中定位正确。
2. **运行与验收必须在 `D:\aa3dpet` 之外进行**（本地已验证可用目录：`D:\petapp`）；源码仍以 `D:\aa3dpet` 为唯一事实来源，运行前同步一次。
3. 本条作为**环境事实**记录，不写入契约规则：契约描述目标平台（Windows 11 x64），不描述某台机器上某个目录的沙箱行为。

## 替代方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 保留 Electron 44（0005） | 运行时更新 | 升级理由已被证伪；跨 11 个大版本还要一轮回归，且 33 在工作区外同样能跑 | 否 |
| 把工程整体搬出工作区（例如 `D:\aa3dpet-app`） | 一次到位，`npm start` 直接可用 | 需要改 §16.1 的根路径与所有文档中的路径，属项目所有者决定 | 待定（不由本 ADR 代为决定） |
| 加 `--no-sandbox` 绕过 | 一行参数 | 无效：`0x80000003` 出现在 sandbox 之前的初始化里；且降低安全性 | 否 |
| 在工作区内继续排查目录为何被区别对待 | 可能根治 | 属于 harness/系统层，不在项目可控范围 | 暂缓（已留证据） |

## 后果

**正面**

- 运行时回到已验证的 `33.4.11`，不再背着一次无理由的大版本跳变。
- 排除了"版本不兼容"与"权限不足"两个误导方向，后续任何人再遇到 `0x80000003` 有明确第一步：**先换到工作区外再跑**。

**负面 / 成本**

- 本地开发多一个动作：改完代码要同步到工作区外目录再运行；验收日志与截图也产生在工作区外。
- 文档必须写清这一点，否则下一个对话会重走一遍这条排查路径。

**约束**

- 不得因为"起不来"再次改动 Electron 版本，除非先排除目录因素（换到工作区外复现）。
- 运行目录若有变更（把工程搬走），必须另出 ADR 并同步 `CONTRACTS.md` §16.1 的根路径。
- `--no-sandbox` 只能作为诊断开关（`PET_CHROMIUM_NO_SANDBOX=1`），不得进入默认启动路径。
