# 0047. 脸部特写取证：眼骨 A/B、准星探针，以及把头部基准从绑定姿态换成站立姿态

| 项 | 值 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-11-05 |
| 决策者 | 项目所有者（真机反馈："瞳孔依然直勾勾地看着下方；你只验证了骨骼的四元数，没有验证最终渲染出来的视线"） |
| 关联 | 契约 §7.3（render 表现规则）、§11（降级）；ADR 0010 D2.6（嘴型图集）、ADR 0014（骨骼仲裁）、ADR 0026 D6.6（表情只走贴图）、ADR 0045 D2.1（头部基准，**基准选取被本 ADR 废止**）、ADR 0046 D1（眼球基底） |

## 背景

ADR 0045/0046 连续两轮都在"用四元数证明她平视"：

- 0045：按**绑定姿态**量出坐姿低头 `+0.262rad`，补 `-0.248rad`；
- 0046：把眼骨基底换成绑定姿态，再叠张望，报出 `eyePitchMean ≈ -0.16`。

真机反馈是"完全翻车，瞳孔还是看下方"。结论很清楚：**四元数指标和画面对不上**，
必须先拿到"渲染出来的像素"，再谈修法。

## 排查（本轮只认像素）

### 1. 先把脸拍大：正交相机特写

脸部在 422×720 的窗口里只有 60–80px 宽，眼睛约 14px——这个尺寸下任何"瞳孔朝哪"的
判断都是猜。裁剪截图再放大只是把模糊放大，所以加了一个**只改视锥**的取证相机
（`setFaceZoom(260)`）：正交相机缩到 260px 方框并每帧跟随头骨，像素密度提高 4–6 倍，
模型、姿态、材质一概不动。取证图：`dist/selftest/face-sit.png`、`face-idle.png`。

### 2. 眼骨 A/B：±0.35rad 的旋转，画面上几乎不动

同一张脸，只给两根眼骨叠加额外 pitch（标定：正 = 低头）：

| 取证图 | 眼骨额外量 | 画面 |
|---|---|---|
| `face-idle.png` | 0 | 虹膜居中，正视 |
| `face-idle-eye-down.png` | +0.35rad（低头 20°） | 与上图几乎一致 |
| `face-idle-eye-up.png` | −0.35rad（抬头 20°） | 与上图几乎一致 |

**20° 的眼球旋转在画面上只挪动两三个像素。** 这与资产事实一致：`CH0335_EyeMouth`
是一张**近乎平贴的卡片**（包围盒 z 厚度 1.4mm），虹膜是**画在贴图上的**，眼骨只带动
整块卡片微小平移/倾斜。也就是说：**视线不是眼骨转出来的，"瞳孔朝哪"由头骨朝向 +
贴图上虹膜的位置共同决定。**

### 3. 头部俯仰 A/B：旧补偿把脸抬过头了

同一张坐姿脸，只在头骨上再叠一个 pitch：

| 取证图 | 头骨额外量 | 画面 |
|---|---|---|
| `face-sit-head-down.png` | +0.25rad（≈ 抵消旧补偿，回到片段原姿态） | 虹膜**回到眼眶中央**，正视镜头 |
| `face-sit.png`（旧补偿） | 0 | 虹膜偏上、眼白在下方 |
| `face-sit-head-up.png` | −0.12rad | 虹膜**顶到眼眶上沿**，明显"看天" |

顺带量到（日志）：站立待机时头骨世界 pitch **−0.032rad**，坐姿片段 **−0.120rad**。
也就是说片段里的头**本来就是微微抬起**的，旧代码却"补了 14° 抬头"——把
`−0.120` 一路推到 `−0.25`，脸卡后仰、虹膜被顶到上沿。真机上那一帧就是"翻白眼/死鱼眼"。

**根因**：`headRawPitch = +0.262rad` 是**相对绑定姿态**（3ds Max 的 T-pose）量的，
而 T-pose 的头本来就压着——这 0.26 里有一大半是参照系误差，不是低头。

### 4. 准星探针（用户要求的"暴力诊断"）

`eyeProbe(true)` 在 `EyeMouth` 贴图上叠三层准星：绿框=标定出的眼区矩形、
品红=眼区 UV 几何中心、青=嘴底板中心。取证图：`dist/selftest/face-probe.png`。

结果（同样是硬证据，记录为已知缺陷）：

- 眼区矩形只覆盖到**单眼内角的一小块**（左右眼两个矩形 UV 完全相同），
  说明现有"按 UV 区域分眼"的标定对这张卡片不成立；
- 青准星落在嘴的下方而非嘴心，底板矩形同样偏。

结论：**眼型差分图层（官方 eyes_*.png）目前无处可画**——这也解释了为什么表情里的
"眼型"一直是 `missing` 降级。这不是本轮引入的问题，但它让"用贴图叠眼型"这条路暂时走不通。

## 决策

### D1 取证工具进代码：脸部特写相机 + 准星探针

- `RenderModule.setFaceZoom(size)`：`size > 0` 时正交视锥缩成 `size×size` 方框并每帧
  跟随头骨（`0` = 恢复铺满窗口）。只动相机，不动模型/姿态/材质。
- `RenderModule.setEyeProbe(enabled)`：在 `EyeMouth` 贴图上叠准星，返回眼区矩形与贴图尺寸。
  关闭时**整张还原**再重绘（准星描边压在脏矩形边界上，局部还原擦不干净——本轮踩过，
  残留的绿框会一直留在脸上）。
- 两个接口都只挂在 `window.diagnostics` 上，属于内部取证，不进 §7.3。

### D2 头部基准：绑定姿态 → **站立待机姿态**

- 新增 `idleHeadPitch`：在"纯待机"的一帧（无拖拽/坐姿/一次性演出/小动作、朝向回正、
  Idle 权重 ≥0.9）采一次头骨的**世界** pitch，作为"她本来就平视"的基准。
- `captureSitHeadLevel()` 改成：`补偿 = idleHeadPitch − 片段世界 pitch`，**只补 pitch**，
  yaw/roll 一律不补（绑定差的 yaw/roll 同样是参照系误差，补了只会让脖子拧着）。
- 补偿量仍按 `sitGain` 淡入，仍夹在 `±SIT_HEAD_LEVEL_MAX_RAD`。
- 实测：`−0.032 − (−0.120) = +0.087rad`（旧实现是 `−0.248rad`，方向没错但量级大了 3 倍）。
- **再补一个固定低头量 `SIT_HEAD_AIM_DOWN_RAD = 0.10`**：只对齐头骨时，特写里虹膜仍偏在
  眼眶上沿（读作"略抬头"）——因为站立时脊柱是直的，而坐姿片段骨盆后倾、躯干略仰，
  **头骨朝向相同不代表脸卡朝向相同**。再低 0.10rad（≈5.7°）虹膜才回到眼眶中央、正对镜头
  （A/B 目视标定：再低 0.25 明显低头显沮丧，0.10 是居中值；`face-sit-compare.png`）。
- 诊断拆成两个口径：`sit.headWorldPitch`（世界、扣微侧身）与 `idleHeadPitch` 对比，
  用来断言"对齐站立"；`sit.headOrientation` 仍保留"相对绑定姿态"口径，只用来量
  **摆动范围**——世界欧拉角在 y≈±90° 附近会退化，拿它量幅度会把 0.24rad 的张望读成
  0.02rad（本轮踩过，自检当场报红）。

### D3 眼球：**不**新增 lookAt 通道（有证据说它没用）

用户要求"每帧 `Object3D.lookAt` 强制看向相机"。本轮用 A/B 证明**这条路在资产上无效**：

- 眼骨 ±0.35rad 对虹膜位置几乎无影响（见排查 2），因为虹膜是贴图；
- `Object3D.lookAt` 还会把骨骼对齐到 +Z 并重算 roll，对这种平贴卡片只会带来新的错位风险。

因此保留 ADR 0046 D1 的"基底 = 绑定姿态 + 张望 × 0.35"，并让**视线方向由 D2 的头部
基准决定**：头骨的世界 pitch 对齐站立姿态再压 0.10rad（= 玩家看到的平视），yaw 跟随
0.15rad 微侧身，所以"看镜头"这件事每帧都由头骨朝向重新算出来，而不是一次性猜出来的角度。

> 如果真机仍然读作"看下方"，下一步不是继续动骨头，而是**贴图**：把虹膜在眼区内的
> UV 整体上移（或做一张"正视"眼型差分图），因为虹膜位置就在贴图上。

### D4 顺带修掉的取证噪声

- `faceDistance` 的基线指纹现在会打日志（`面部基线指纹 …`），贴图每次**变化**也打一条
  （指纹 + 当前嘴层 + 眼层 + 距离），用于定位"表情结束后回不到基线"。

## 替代方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 每帧 `Object3D.lookAt` 强制眼骨 | 字面满足需求、方向绝对可控 | 实测虹膜几乎不动；还会重算 roll，把平贴卡片转歪 | 否（D3） |
| 把眼骨旋转幅度调大（±0.8rad） | 不改架构 | 卡片被转歪、眼白/虹膜比例失真，仍不是"看向相机" | 否 |
| 直接 UV 偏移虹膜 | 从根上改视线 | 需要逐张核对贴图；眼区 UV 标定目前不可用（排查 4） | 暂缓（下一步） |
| FaceDecal 叠一张正视眼型 | 不动骨骼、可控 | 官方眼型图缺失 + 眼区标定不可用，先要修标定 | 暂缓 |
| 头部基准继续用绑定姿态 | 不动代码 | 参照系误差 0.13rad，实测"翻白眼" | 否（D2） |
| 头部基准改用站立姿态（本方案） | 与玩家看到的一致、可复现 | 需要先采一次待机姿态，且要再补 0.10rad 才真的正对镜头 | **是** |

## 后果

**正面**

- 坐姿头部姿态 = 站立姿态 + 0.10rad 低头；脸部特写下虹膜回到眼眶中央、正对镜头（`face-sit.png`）。
- 取证工具留在代码里：以后任何"眼神/嘴型"争议都能用 260px 特写 + 准星直接看图。
- 准星关闭不再留残影。
- 主链路自检 172 条全绿（新增脸部特写 3 条、改写头部/眼球 2 条）。

**负面 / 成本**

- 站立基准只在第一次纯待机时采一次；如果模型/骨架换了，需要重新确认这个数。
- `SIT_HEAD_AIM_DOWN_RAD = 0.10` 是目视标定值，换模型/换表情贴图要重看 `face-sit-compare.png`。
- 眼型差分图层仍然画不出来（眼区标定缺陷，排查 4），表情的"眼睛"依旧降级。
- `sit.headOrientation` 的口径从"相对绑定"改成"世界"，旧日志不可直接对比。

**约束**

- 不得用代码写眼皮骨（`bone_eye_D_*`）的任何通道（沿用 0046）。
- 取证接口只允许挂在 `window.diagnostics`，不得进 §7.3 或 IPC。
- 头部补偿只允许改 pitch；yaw/roll 补偿一律为 0。
- 所有幅度/周期只写在 `shared/constants.ts`。
